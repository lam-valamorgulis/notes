Study Plan — Claude Certified Architect: Foundations

Self-paced. Built from the official Exam Guide (v1.0). Five weighted domains, ordered by weight × your likely gap. The exam is scenario-based judgment — 60 questions, 4 of 6 scenarios, 120 minutes, pass at 720/1000. So for every box, don't just learn the fact — practice picking the most effective fix and saying why the other options are worse.

The 5 themes that decide most questions. Drill these until they are reflex: (1) deterministic enforcement (hooks / prerequisite gates) beats prompting when errors are costly. (2) fix the root cause cheaply first (better tool description) before big hammers (routing layer, classifier, more few-shot). (3) explicit criteria beat sentiment / self-reported confidence. (4) least privilege — give an agent only its role's tools. (5) pass structured data (IDs, dates, claim→source), not prose, between agents.

Domain 1 — Agentic Architecture & Orchestration 27% · biggest start here

Goal: understand the agentic loop and multi-agent coordination. Highest weight, and it underpins everything else. Open Lesson 1 →

  • learn The agentic loop: send request → check stop_reason ("tool_use" = keep going, "end_turn" = done) → run tool → append tool_result → repeat. Anti-patterns: parsing natural language to decide when to stop, or capping iterations as the main stop. (docs)
  • learn Coordinator–subagent (hub-and-spoke): coordinator does task decomposition, delegation, aggregation, routes all sub-agent traffic for observability. Risk: too-narrow decomposition misses parts of a broad topic (sample Q7). (docs)
  • learn Subagent context is fresh — they do NOT inherit the parent's history. Pass everything they need in the prompt; separate content from metadata (source URLs, dates). AgentDefinition, spawn via the Task/Agent tool, allowedTools must include it. Parallel = multiple Task calls in one response.
  • learn Enforcement & handoff: prerequisite gates block downstream tools until a step completes; structured handoff summaries (customer ID, root cause, action) for human escalation.
  • learn Agent SDK hooks (PostToolUse): intercept tool results to normalize data, or intercept outgoing calls to block policy violations (refund > $500). Hooks = guaranteed compliance; prompts = probabilistic. (TS ref)
  • learn Task decomposition: fixed prompt-chaining (predictable multi-aspect reviews) vs dynamic adaptive decomposition (open-ended investigation).
  • learn Session state: --resume <name>, fork_session for divergent branches from a shared baseline; start fresh with a summary when prior tool results are stale.
  • drill Decision drill: "An agent skips identity check before refunds 12% of the time. Prompt harder, few-shot, routing classifier, or a prerequisite gate?" (Answer: gate — deterministic. Sample Q1.)

Domain 4 — Prompt Engineering & Structured Output 20%

Goal: get reliable, schema-valid output and cut false positives. Tightly linked to Domain 2. Open Lesson 2 →

  • learn Explicit criteria beat vague instructions ("flag only when a comment contradicts actual behavior" > "check comments are accurate"; "be conservative" does not help). High false-positive categories destroy trust — sometimes disable them while you fix. (Sample Q… review scenario)
  • learn Few-shot: 2–4 targeted examples for ambiguous cases, showing the reasoning for choosing one action over a plausible alternative; demonstrate the exact output format; enable generalization to novel cases.
  • learn Structured output via tool_use + JSON schema — the reliable path; eliminates syntax errors (not semantic ones). tool_choice: auto vs any (must call some tool) vs forced {"type":"tool","name":"..."}; strict: true. (docs · forcing)
  • learn Schema design: optional/nullable fields so the model returns null instead of fabricating; enum "other" + detail string for extensible categories; "unclear" for ambiguity.
  • learn Validation-retry loops: on failure, resend document + failed extraction + specific error. Retry helps for format/structural errors — NOT when the info is simply absent from the source.
  • learn Message Batches API: 50% cost, up to 24h, no latency SLA, no multi-turn tool calls, custom_id to correlate + resubmit failures. Fits overnight/latency-tolerant work; not blocking pre-merge checks. (docs)
  • learn Multi-pass / multi-instance review: an independent review instance (no generation context) catches more than self-review; split big reviews into per-file + cross-file passes to beat attention dilution (a bigger context window does not fix it — sample Q12).
  • drill Decision drill: "Extraction must never invent a missing field. What in the schema + prompt guarantees that?" (Nullable fields + instruction; retry won't create absent data.)

Domain 2 — Tool Design & MCP Integration 18%

Goal: design tools Claude selects correctly, and wire up MCP servers. (Hosting/deploying MCP servers is OUT of scope.) Open Lesson 3 →

  • learn Tool descriptions are the primary selection signal. Minimal/overlapping descriptions cause misrouting (get_customer vs lookup_order). Fix = better descriptions (input formats, examples, edge cases, when-vs-similar) — the cheap root-cause fix, not a routing layer. (Sample Q2)
  • learn Split generic tools into purpose-specific ones with clear I/O contracts (analyze_document → extract_data_points, summarize_content, verify_claim_against_source).
  • learn Structured errors: MCP isError flag; return errorCategory (transient / validation / permission), isRetryable boolean, human-readable message. Distinguish access failures (retry) from valid empty results (no matches). Generic "operation failed" hides recovery info.
  • learn Tool distribution / least privilege: too many tools (18 vs 4–5) degrades selection; give agents only their role's tools; scoped cross-role tools for high-frequency needs (verify_fact for synthesis). tool_choice "any" or forced to guarantee/order calls.
  • learn MCP scoping: project .mcp.json (shared, version-controlled) vs user ~/.claude.json (personal); env-var expansion ${GITHUB_TOKEN} for secrets; all servers' tools available at connect time; MCP resources expose content catalogs to cut exploratory calls. Prefer community servers for standard integrations (Jira). (Claude Code MCP · MCP architecture)
  • learn Built-in tools: Grep (content search), Glob (path patterns), Read/Write (full file), Edit (unique-match), Bash. Build understanding incrementally: Grep for entry points → Read to follow imports.
  • drill Decision drill: "A synthesis agent keeps trying web searches it shouldn't. Best fix?" (Restrict its tool set — least privilege — not more instructions.)

Domain 5 — Context Management & Reliability 15%

Goal: keep critical info alive across long runs, and make sound escalation / error / review decisions. Mostly judgment patterns (few docs). Open Lesson 4 →

  • learn Preserve facts: put amounts, dates, order IDs, statuses in a persistent "case facts" block, not in progressive summaries (which blur numbers). Trim verbose tool outputs (40+ fields → the 5 relevant) before they fill context.
  • learn "Lost in the middle": models read the start and end of long inputs reliably, may drop the middle. Put key findings first; use explicit section headers.
  • learn Escalation: escalate on explicit customer request, policy gaps/silence, or no progress — NOT on sentiment or self-reported confidence (poorly calibrated). Ask for more identifiers when a lookup returns multiple matches. (Sample Q3)
  • learn Error propagation: return structured error context (failure type, attempted query, partial results, alternatives) so the coordinator can recover; never silently swallow errors (empty = success) or kill the whole workflow on one failure. (Sample Q8)
  • learn Large-codebase context: subagents to isolate verbose exploration; scratchpad files to persist findings across context boundaries; /compact during long sessions; structured state exports (manifests) for crash recovery.
  • learn Human review & confidence: stratified sampling of high-confidence extractions to catch novel errors; calibrate field-level confidence with labeled sets; check accuracy per document type/field, not just an aggregate (97% overall can hide a bad segment).
  • learn Provenance: keep claim→source mappings through synthesis; annotate conflicting values with their sources (don't pick one); include publication/collection dates so time differences aren't read as contradictions.
  • drill Decision drill: "A web-search subagent times out. How should the failure reach the coordinator?" (Structured error context — type, attempted query, partial results — not a generic 'unavailable' or a killed workflow.)

Domain 3 — Claude Code Configuration & Workflows 20% · likely your strength convert habit → exam answers

Goal: turn daily Claude Code use into exact, named, defensible answers. Do this last — high weight, but you already live it; drill the vocabulary. Open Lesson 5 →

  • learn CLAUDE.md hierarchy: user (~/.claude/CLAUDE.md, personal, not shared), project (.claude/CLAUDE.md or root), directory-level. @import to stay modular; /memory to see what's loaded. Diagnose "teammate not getting instructions" = they're in user-level, should be project-level. (docs)
  • learn .claude/rules/ with glob path-scoping: YAML paths: (e.g. ["**/*.test.tsx"]) loads rules only when editing matching files — the right choice for conventions spread across many directories (beats a subdirectory CLAUDE.md). (Sample Q6) (settings)
  • learn Slash commands: project .claude/commands/ (shared, version-controlled — the answer for a team-wide /review) vs user ~/.claude/commands/ (personal). (Sample Q4) (docs)
  • learn Skills (SKILL.md frontmatter): context: fork to isolate verbose/exploratory output from the main session; allowed-tools to restrict; argument-hint to prompt for params. Skills = on-demand; CLAUDE.md = always-loaded. (docs)
  • learn Plan mode vs direct execution: plan mode for large-scale / multi-approach / architectural / multi-file work (safe exploration before committing); direct for simple, well-scoped changes. Use the Explore subagent for verbose discovery. (Sample Q5)
  • learn CI integration: -p / --print for non-interactive (stops the hang — sample Q10); --output-format json + --json-schema for machine-parseable findings; put review criteria/fixtures in CLAUDE.md; an independent instance reviews better than the one that wrote the code. (CLI ref)
  • drill Decision drill: "A team /review command must reach every dev on clone. Where does it live?" (.claude/commands/ in the repo, not ~/.claude/ — sample Q4.)
If you have limited time Weight-first, never-skip core: Domain 1 (27%) → Domain 4 (20%) → Domain 3 (20%). These are 67% of the exam. Then Domain 2 (18%) and Domain 5 (15%). Within each, the 5 themes in the box above answer most questions — learn the theme, not 100 facts.
