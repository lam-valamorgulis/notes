The big picture — how it all connects

Everything on this exam grows from one idea: an agent is not a single answer, it is a loop. So we begin with agentic architecture — how the loop knows when to stop, and when one agent should hand work to a coordinator and subagents. That loop is only as good as what flows through it. So next we make the model's output trustworthy from two sides: prompt engineering and structured output makes each answer schema-valid and low on false positives, and tool design and MCP makes the model pick the right tool and fail in a way you can recover from.

A long run then has to stay correct, so context management and reliability teaches you to keep the key facts alive, escalate for the right reasons, and pass errors as structured data. With the theory in hand, we turn to your home turf — Claude Code configuration and workflows — and convert daily habit into the exact, named answers the exam wants. Finally we prove it under time pressure with the exam strategy and full mock. Three themes recur in almost every question. Deterministic enforcement beats prompting when the rule is a bright line and errors are costly — but the reverse holds when the condition is open-ended judgment, because code can only enforce what you can fully write down. Fix the cheap root cause (a better tool description) before reaching for a big hammer. And distrust the option that fails silently — an empty result returned as success, a truncated answer treated as finished, a summary that dropped the amount. A system that crashes gets fixed; a system that lies gets trusted.
