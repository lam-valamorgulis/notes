4. The 6 master keys (this is how you pass)

Almost every hard question is one of these 6 judgment themes in a costume. Learn the theme and you can answer questions you have never seen.

Key 1 — Determinism beats prompting when the line is bright and errors are costly When a mistake costs money or touches identity, enforce the rule in code — a hook or a prerequisite gate — not in a prompt. Prompts are probabilistic: they work most of the time, and "most" is not good enough for a refund.

Both halves, or you will get caught. Code can only enforce a condition you can write down completely — an amount to compare, a step that must have happened. When the condition is open-ended judgment ("does this customer actually need a human?", "is this progress?"), code stops being more reliable than the model and becomes reliably wrong on every case you failed to list. So the question is never "is this important?" — important things point at code. It is "can I state the whole rule?" Yes → code. No → the model, with explicit written criteria. An option that hooks a judgment call is as wrong as an option that prompts a bright line.

Key 2 — Fix the cheap root cause first Before you reach for a big hammer (a routing layer, a trained classifier, more few-shot examples, a bigger context window), fix the simple root cause: a thin tool description, a vague instruction, missing criteria. Pick the proportionate first response.
Key 3 — Explicit categorical criteria win Clear, listed rules ("escalate if X, Y, or Z") beat vague instructions ("use good judgment") and beat sentiment or self-reported confidence. The model should match a case to a named category, not guess a feeling.
Key 4 — Least privilege for tools Give an agent only the tools its role needs. A synthesis agent does not need web search. For a high-frequency cross-role need, give a narrow scoped tool — not the full set.
Key 5 — Pass structured data between agents Move IDs, dates, claim-to-source links, and structured error context between agents — not prose. Prose loses facts and provenance. Structure preserves them.
Key 6 — Prefer the failure that announces itself The most dangerous option in any question is usually the one that fails silently — nothing crashes, nothing is logged, and a wrong answer is reported as a finished one. Once you can see this shape, it appears in every domain: a loop that treats any non-tool stop as "done" (so truncated output ships as complete), a subagent that returns an empty list instead of its timeout (so the coordinator trusts a lie), a summary that quietly drops the amount and the date, a merge that drops which source said what, appending only the text and losing the state that came with it. Given two options, the better one is almost always the one that makes the failure visible — surface the conflict, return the partial result and the error, annotate the gap. Surface, don't guess. Preserve, don't discard.

5. How to eliminate the 3 wrong options

Every question has 1 right answer and 3 traps. The traps almost always fall into these buckets. Name the bucket, cross it out.

Trap typeHow to spot it
Over-engineersAdds a classifier, routing layer, or new model when a one-line fix would do. Cross out if a cheaper cause is unaddressed.
Treats a symptomRetries, "remind the model", "summarize harder" — patches the effect, ignores the cause.
Trusts probability where you need certainty"Stronger prompt", "add examples", "ask it to double-check" for a money/identity rule. Determinism is required — cross it out.
Blames the wrong componentFixes the search agent when the coordinator decomposed the task wrong. Trace the failure to its true source.
Invents API surfaceA flag, environment variable, or config field that does not exist — --batch, CLAUDE_HEADLESS, a "commands" array in a config file. Most common in Domain 3. Two tells: it is named exactly after the problem (a hanging job "fixed" by a --headless flag), and you cannot picture it in the real reference. The genuine flag is usually the plainer one.
Fails silentlyReturns empty as success, swallows the error, drops the sources, treats a truncated answer as finished. Nothing crashes — which is exactly why it is the worst option, not the safest. Prefer the choice that surfaces the problem.
The one habit that raises your score

Read the last line of the question first — usually "What is the MOST effective ...?". Then read the options and ask of each: does this over-engineer, treat a symptom, trust probability where I need certainty, or blame the wrong part? Cross out the three that do. The one left is almost always right.

Time trap 2 minutes per item is enough — if you do not stall. Flag any item you are unsure about, pick your best guess now, and move on. Never leave a blank; there is no penalty for guessing. Come back with your remaining time.
