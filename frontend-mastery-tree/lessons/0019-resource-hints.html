Stratum 3 · Network & Delivery · Protocol · Lesson 0019

Resource hints: preconnect, preload, prefetch, fetchpriority

The browser starts a fetch when it discovers the URL. Everything in this lesson is a way to say "you will need this — start earlier" — and each hint moves a different block of lesson 0017's timeline.

core Domain expertise: moves ability #2 (predict an unseen case) and ability #5 (judge someone else's work) — hints are the most commonly cargo-culted lines in any theme's <head>, and half of them are doing nothing.

The win: after ~30 minutes you can pick the correct hint for a given problem in one sentence, explain why adding more of them makes things worse, and audit a <head> full of inherited hints and say which to delete.

1. Each hint removes a different block

Lesson 0017 gave the four blocks before a first byte: DNS, TCP, TLS, then the request. A hint does not make the network faster — it moves work earlier, so it overlaps other work instead of queueing behind it. Which block it moves is the whole difference between the hints:

2. The four, with the mistake that comes with each

HintUse it whenThe usual mistake
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>you know an origin will be needed early and cannot avoid itpreconnecting to eight origins — sockets and bandwidth are finite, so keep it to two or three that matter
<link rel="preload" as="font" type="font/woff2" href="…" crossorigin>a resource is critical but discovered late — a font referenced inside CSS, a hero image built by scriptpreloading something the parser would have found anyway: no gain, and you compete with what actually matters
<link rel="prefetch" href="/collections/all">you are fairly confident where the user goes nextprefetching many pages on a phone — you spend the customer's data on a guess
<img fetchpriority="high" …>the LCP image should outrank other images the browser already foundmarking several things high — priority is an ordering, so if everything is high nothing is
Trap — the three ways preload backfires

1. Missing or wrong as. Without it the browser cannot guess the priority or apply the right Content Security Policy, and it may fetch the file twice.

2. Missing crossorigin on a font. Fonts are fetched in anonymous mode, so a preload without crossorigin does not match the real request and you download the font twice.

3. Preloading and not using it. Chrome logs a warning: "The resource … was preloaded using link preload but not used within a few seconds". That is pure wasted bandwidth on a mobile connection, and it is the most common leftover in an inherited theme.

3. Preferring the plain fix over the hint

A hint is a patch over a discovery problem. It is usually better to remove the discovery problem, and knowing which to reach for is the senior judgement here:

ProblemHint answerBetter answer
Hero image found late because it is lazy-loadedpreload itremove loading="lazy" and add fetchpriority="high" — the parser then finds it immediately (lesson 0016)
Font found late because it lives inside a stylesheetpreload the font fileself-host it and preload it — or accept a system font for the first paint with font-display: swap
Third-party origin is slow to connectpreconnectdelete the origin, or defer the script so its connection is off the critical path (lesson 0017)
Script-built image URLs are invisible to the preload scannerpreload each oneput the real src in the markup, so the scanner from lesson 0011 does the work for free

Read the right-hand column again: three of the four better answers are just "let the browser discover it normally". Hints are for the cases where you genuinely cannot.

4. Explain it back Feynman check

Part 1 · Plain words — no jargon at all

The browser only starts fetching a file when it reads the line that mentions it. If an important file is mentioned somewhere deep — inside another file, or in code that runs later — it starts late, and everything waits. These instructions let you say up front: "look up this company's address now", or "open the line to them now", or "start downloading this exact file now". You are not making the network faster. You are starting the wait earlier, so it happens while other work is going on.

Part 2 · One analogy, and where the analogy breaks

The analogy. Cooking. You put the water on to boil before you start chopping, because the boiling will happen anyway and it may as well happen while your hands are busy. That is preconnect and preload: the same total work, started sooner.

Where it breaks. In a kitchen you can put six pans on and it costs only attention. Here every early fetch competes for one connection budget and one radio. Preconnect to eight origins and you have not started eight things early — you have made them queue against each other and stolen bandwidth from the file that mattered. And prefetch has no kitchen equivalent at all: it is cooking a meal the guest may never order, paid for with their data.

Part 3 · The sticking point

People treat hints as free speed and add them in bulk. Priority is relative: marking five things high is the same as marking none. Bandwidth is shared: an early fetch you did not need delays one you did. The second sticking point is confusing preload with prefetch. preload is "this page, now, high priority — I promise to use it". prefetch is "maybe the next page, whenever there is nothing better to do, feel free to discard it". One word apart, opposite urgency.

Part 4 · Teach it back to me

Two or three sentences to a teammate who added preconnect for all eleven third-party origins in theme.liquid and reports "no improvement". Explain why, and say which two you would keep. Then send it to me — I am checking that you talk about competition for a shared budget rather than saying "too many hints is bad practice".

5. Point at it: check every hint is earning its place gate #3

  1. List what the page already asks for. In the Console: [...document.querySelectorAll('link[rel*="pre"],link[rel="modulepreload"]')].map(l => l.rel + ' → ' + l.href). On an inherited theme this list is usually longer than anyone expects, and nobody knows who added what.
  2. Find the wasted ones. Reload with the Console open and search for the word preloaded. Chrome's "preloaded but not used" warning names each hint that is pure waste. Deleting those is a free, zero-risk win — and it is gate #3 for this core.
  3. Check the priorities. Network panel → right-click the header row → enable Priority. Sort by it. Your LCP image should be at or near the top; if a chat widget's script is above it, that is the ticket.
  4. Verify a preconnect actually helped. Compare the Timing tab of the first request to that origin, with and without the hint. With a working preconnect, DNS, connection and SSL show as already done. If they do not, the hint fired too late or the origin was wrong — a preconnect placed after the blocking scripts in the head does almost nothing.
  5. Watch for the double download. Filter the Network panel by the font's filename after adding a font preload. Two entries means a mismatch: usually a missing crossorigin or a wrong as.
Work drill — do this on a real theme

An inherited theme.liquid head contains: preconnect to 7 origins; preload as="script" for theme.js which is also loaded with defer two lines below; a font preload with no crossorigin; prefetch for three collection pages; and no hint at all for the hero image, which sits inside a slider section with loading="lazy". The console shows two "preloaded but not used" warnings, and the font appears twice in the Network panel.

Before flipping the recall cards: go line by line and say keep, fix or delete, with the reason in mechanism terms. Then the interviewer's follow-up: after your clean-up the LCP improves by 700 ms — which single change do you believe was responsible, and how would you prove it rather than claiming it?

6. Live coding session

Type it, predict it, break it

Make a page that loads a font from a stylesheet — the classic late-discovery case. Type it by hand:

<!doctype html>
<link rel="stylesheet" href="styles.css">
<h1>Late-discovered font</h1>

/* styles.css */
@font-face { font-family: T; src: url('/font.woff2') format('woff2'); font-display: swap }
h1 { font-family: T, serif }

Predict before running: in the Network waterfall, when does font.woff2 start relative to styles.css? Serve it, throttle to Slow 4G, and look. The font cannot start until the CSS has arrived and been parsed and matched to an element — a serial chain, exactly like the @import problem in lesson 0010.

Now add the hint and predict how the waterfall changes before you reload:

<link rel="preload" as="font" type="font/woff2" href="/font.woff2" crossorigin>

The font's bar should now start next to the stylesheet's rather than after it.

Break it on purpose, twice. First remove crossorigin, reload, and count the font.woff2 entries — predict the number first. Then put crossorigin back and remove as="font", and watch the Priority column change. Two one-word edits, two different failures, both common in real themes.

Third round — prove that priority is relative. Add four images and mark them all high:

<img src="a.jpg" fetchpriority="high"><img src="b.jpg" fetchpriority="high">
<img src="c.jpg" fetchpriority="high"><img src="d.jpg" fetchpriority="high">

Predict: does a.jpg arrive sooner than it did with no hints at all? Then mark only a.jpg high and the other three low, and compare. Watching the first version achieve nothing is the most useful five minutes in this lesson.

7. Prove it

The gate — only now touch the tracker Open the tree tracker and mark resource hints: preconnect, preload, prefetch, fetchpriority done only if all three held, from memory: (1) you explained the eleven-preconnect problem as competition for a shared budget — the teach-back in section 4; (2) you predicted the double font download, and predicted that four high images would gain nothing; (3) you audited a real <head>, found a "preloaded but not used" warning or a mis-ordered Priority column, and deleted or fixed it. Two out of three is zero out of three.

Remember this
  • A hint does not speed up the network. It starts the wait earlier, so it overlaps other work.
  • Pick by block: dns-prefetch = DNS · preconnect = DNS + TCP + TLS · preload = the request itself.
  • preload is "this page, now, I will use it". prefetch is "maybe next page, lowest priority, discardable".
  • fetchpriority reorders fetches the browser already knows about. Priority is relative — everything high means nothing is.
  • Three preload failures: missing as, missing crossorigin on a font, and never using it (Chrome warns).
  • Keep preconnect to two or three origins. Sockets and bandwidth are shared and finite.
  • Prefer removing the discovery problem: real src in the markup, no loading="lazy" on the hero, one fewer origin.
  • Audit with the Console warning and the Network panel's Priority column, never by reading the head and hoping.

If you remember one thing: if you cannot name the block a hint moves, delete the hint.
