Memory & leaks — cheat sheet

The compressed core of lesson 0009, in the order you use it during a real leak hunt.

The one sentence: the collector frees what is unreachable, never what is "unused" — so ask "what still points at this?", never "why has this not been freed?"

Roots — alive by definition

- the global object and everything hanging off it (window.*) - every frame currently on the call stack, and its variables - things the PLATFORM holds: the live document tree registered event listeners pending timers (setTimeout / setInterval) in-flight requests anything reachable from a root by any chain of references is KEPT.

The four leak shapes

ShapeThe ropeWhat it keepsFix
Detached DOMa variable, array or Map still referencing a removed nodethe node and its whole subtreenull the reference on removal; key caches with WeakMap; unobserve observers
ListenersaddEventListener on a long-lived target whose handler closes over your componenthandler box → component → its DOMone AbortController per instance, abort() on teardown
TimerssetInterval never cleared — a pending timer is a rootthe callback's whole box, foreverclearInterval on teardown; prefer self-stopping rAF loops
Closuresany surviving function created in a big scopeevery binding its box holdsclose over the id, not the component
The listener myth Listeners do not always leak. If the target node and the handler become unreachable together, both are collected — no removeEventListener needed. The leak is when the target outlives the component: window, document, or a node something else still holds. The question is never "did I remove it" but "how long does the target live?"

The hunt, in order

1. TREND Performance monitor -> JS heap size + DOM Nodes staircase that never falls = leak. sawtooth = healthy. 2. CULPRIT Memory -> Heap snapshot, three times: snap 1 -> do the action x10 -> snap 2 -> x10 again -> snap 3 compare 3 vs 2. what grows between two IDENTICAL rounds is the leak. 3. SHAPE in a snapshot, filter the class list for "Detached" 4. ROPE select one -> RETAINERS pane -> names the object, property, often the file and line. that is the line you change. 5. CONFIRM for a timer suspicion: for (let i = 1; i < 9999; i++) clearInterval(i) force GC (bin icon), re-snapshot. gone? it was a timer root.

Shopify theme shape: re-initialised sections

// leaks once per section re-render (theme editor, Section Rendering API) function init(section) { window.addEventListener('resize', () => layout(section)); // window OUTLIVES the section setInterval(() => advance(section), 4000); // a pending timer is a root } // one controller per instance — one line cuts every rope function init(section) { const ac = new AbortController(); window.addEventListener('resize', () => layout(section), { signal: ac.signal }); const id = setInterval(() => advance(section), 4000); section.addEventListener('shopify:section:unload', () => { ac.abort(); clearInterval(id); }, { once: true }); }

Vocabulary that keeps you honest

Say thisNot thisBecause
"nothing can reach it""it is not used any more"usage is not a thing the collector can know
"detached, but still reachable""removed, so it should be gone"remove() unlinks from the document; it frees nothing
"the target outlives the component""I forgot to remove the listener"points at the actual condition, so you fix the right ones
"a rope to a function is a rope to its whole box""closures leak"lesson 0003's rule, applied to memory — not a new rule
