Reference · shared vocabulary

Glossary

One agreed wording per term. Every lesson uses the wording on this page — if a lesson says it differently, this page wins and the lesson is wrong.

How to use it: when a term feels slippery in an interview, read the plain words column out loud first, then the precise one. A definition you cannot say in plain words is a definition you have memorised, not understood.

Chapter 1 · Language & Runtime

TermPlain wordsPreciseLesson
execution contextone note about one running callThe record the engine creates per running call: where it is in the code, its variable bindings, its this.0001
call stackthe pile of notes, newest on topThe last-in-first-out stack of execution contexts. One per agent (roughly, per tab).0001
frameone note in the pileOne entry on the call stack. What DevTools lists in the Call Stack pane.0001
lexical environmenta box of names plus one arrow outwardAn environment record (the bindings declared right here) plus a reference to the outer environment, fixed at creation time by where the code is written.0002
scope chainfollow the arrows outward until you find the nameThe sequence of outer references followed during name resolution. Outward only — never inward, never by caller.0002
shadowingthe nearest name winsAn inner binding with the same name as an outer one; lookup stops at the first match, so the outer binding is unreachable by that name from inside.0002
closurea function that kept its box aliveA function together with the lexical environment it was created in. The environment is shared and live, never copied.0003
call sitethe exact place the call was writtenThe expression that performed the call. It decides this for a normal function — and nothing else in this branch.0004
task (macrotask)one whole job the browser agreed to runA queued unit of work the event loop picks up: a script, an event callback, a setTimeout callback. One task runs to completion per turn.0005
microtaska small job that must run before the browser is allowed to breatheA job on the microtask queue (promise reactions, queueMicrotask, MutationObserver). The queue is drained to empty after the current task, before rendering.0006
long taskone job that hogged the threadA task occupying the main thread for 50 ms or more. Everything queued behind it waits, including the user's click.0007
settledthe answer arrived and can never changeA promise that is fulfilled or rejected. State transitions happen once; pending → fulfilled|rejected is one-way.0008
reachablesomething still holds a rope to itReachable from a GC root by any chain of references. Reachable means kept, whether or not you still want it.0009
detached DOM noderemoved from the page, still held in JavaScriptA node no longer in the document tree but still referenced by a live variable, closure or listener — so it cannot be collected.0009

Chapter 2 · Rendering Pipeline

TermPlain wordsPreciseLesson
CSSOMthe browser's parsed copy of your CSSThe CSS Object Model: every rule parsed into a structure the engine can match against elements. Incomplete CSSOM means no correct styles, so it blocks rendering.0010
render-blockingthe browser refuses to paint until this arrivesA resource the browser must have before it can produce the first frame. Stylesheets in <head> are the usual case.0010
parser-blockingthe HTML reader stops deadA resource that halts HTML parsing where it sits — a classic <script> with no defer, async or type=module.0011
specificityhow loudly a selector claims an elementThe (id, class, type) count compared left to right, used only after origin and layer have been decided.0012
reflow / layoutwork out where every box goesComputing geometry — position and size — for the affected part of the box tree. The most expensive step you can trigger from JavaScript.0013
compositeslide finished pictures aroundCombining already-painted layers, on the compositor thread. transform and opacity can be done here with no layout and no paint.0013
forced synchronous layoutyou asked for a number, so layout had to happen nowReading a geometry property (e.g. offsetHeight) while style or layout is dirty, which forces the engine to lay out immediately, mid-script.0014
frame budgetabout 16 ms to do everything, sixty times a secondAt 60 Hz, ~16.67 ms per frame for script, style, layout, paint and composite combined. Over budget = a dropped frame.0015
LCP / CLS / INPhow fast the big thing showed · how much it jumped · how slow it felt to touchLargest Contentful Paint, Cumulative Layout Shift, Interaction to Next Paint — the three Core Web Vitals, each with a field-data threshold.0016

Chapter 3 · Network & Delivery

TermPlain wordsPreciseLesson
RTTone there-and-back tripRound-trip time: latency for a packet to reach the server and its reply to return. The unit connection setup is priced in.0017
fresh / stalestill usable without asking · must ask firstA cached response inside its freshness lifetime is fresh and served with no request. Past it, it is stale and needs revalidation.0018
revalidation"is my copy still good?"A conditional request (If-None-Match / If-Modified-Since) that can answer 304 Not Modified with no body — still a full round trip.0018
resource hinttelling the browser early what you will needpreconnect, preload, prefetch, fetchpriority — each changes when or in what order a fetch happens, never whether the byte count exists.0019
waterfallthe picture of what waited for whatThe Network panel's timeline of requests. Steps down the page mean a dependency chain; a flat block means parallel fetches.0020
idempotentdoing it twice is the same as doing it onceA request that can be safely repeated without changing the result again. Retrying a non-idempotent request can double-charge a customer.0021
jitterdeliberately uneven waitingRandomness added to a retry delay so that many clients do not retry in the same instant and re-crash the server.0021
Rule for this page A term enters the glossary the moment a lesson uses it twice. If you catch a lesson using a term that is not here, or defining one differently, tell me — the fix belongs on this page first, then in the lesson.
