Network & delivery — cheat sheet

The compressed core of lessons 0017–0021. Chapter 3 is four moves: do not open a connection, do not make a request, start it earlier, fail safely.

What a request costs lesson 0017

new origin: [ DNS ][ TCP ][ TLS ][ REQUEST ] -> first byte ~1 RTT ~1 RTT ~1 RTT ~1 RTT ≈ 4 RTTs reused: [ REQUEST ] -> first byte 1 RTT RTT: 10-30ms good wifi · 100-200ms MOBILE => a new origin is ~600ms of nothing at 150ms RTT, IDENTICAL for a 2KB file and a 200KB file. LATENCY is the bottleneck, not bandwidth. a faster link does not shorten a handshake. TCP SLOW START: the window begins ~14KB and doubles per RTT — which is why a small first payload arrives disproportionately sooner, and why inlining the first screen works. HTTP/2 reuses ONE CONNECTION PER ORIGIN. it never makes an extra origin free.

Count origins on any storefront: new Set(performance.getEntriesByType('resource').map(r => new URL(r.name).origin)).size — then multiply (n - 1) × 3 RTT × 150 ms. That number persuades people.

Failing safely lesson 0021

delay = random(0, min(cap, base * 2^attempt)) <- full jitter BACKOFF protects the server. JITTER protects it from your other clients. you need both; they solve different problems. retry: network failure · 408 · 425 · 429 · 500 · 502 · 503 · 504 NEVER: 400 · 401 · 403 · 404 · 422 obey Retry-After when the server sends it — it beats your arithmetic. always: a per-request timeout (AbortController), a delay cap, bounded attempts.
The expensive half A timeout means you stopped waiting, not that nothing happened — the server may have completed the work. Retry a non-idempotent POST and the customer gets two of the item. Defences, strongest first: an idempotency key (needs the server); reconcile (re-read the state, e.g. GET /cart.js, and act on that); ask the user with an explicit failure and a manual retry. On a storefront you rarely own the endpoint, so the last two are the real options. Good backoff maths never makes an unsafe retry safe.

And the interface half: keep anything a customer is waiting on bounded to a few seconds, show the retrying state, and always leave a manual retry. Silent retries are for background work only.
