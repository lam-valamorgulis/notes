Bulk Operations

How Shopify hands you huge datasets without hitting the rate limit — a job, a file, and a sorting trick.

Your win: answer "How do bulk operations actually return data, and when do you use them?" — clearly, out loud.

Ties to your mission: this is the standard way to do the initial full import in a Shopify↔ERP sync (L5, L11) and the answer to "export a million products".

Why this lesson is here: it is a Day-1 insert, so its number (18) is out of order. Read it right after the Shopify core lessons; the footer sends you back to L6.

1. The one idea: a job, not a request

A normal GraphQL query is a request — you ask, you get data back right away. A bulk operation is a job — you start it, Shopify works in the background, and later gives you a file to download. Lock that in; everything else follows from it.

The warehouse picture A normal query is asking a clerk at the counter for a few items — fast, but ask for too much and they say "slow down" (the rate limit). A bulk operation is handing the warehouse a big order form: they pack it in the back (no clerk, no limit) and later give you one big box plus a pickup slip (a download link).

2. The four steps

1. START bulkOperationRunQuery(query: "...") → job created 2. WAIT currentBulkOperation { status url } → CREATED → RUNNING → COMPLETED 3. DOWNLOAD when COMPLETED, GET the `url` → one JSONL file 4. SORT read the file line by line → rebuild your data

Start, wait, download, sort. Note: a bulk query has no first: arguments inside it — the whole point is that it fetches everything, not one page.

Start the job

mutation {
  bulkOperationRunQuery(query: """
    { orders { edges { node {
        id name createdAt
        lineItems { edges { node { id name quantity } } }
    } } } }
  """) {
    bulkOperation { id status }
    userErrors { field message }
  }
}

Check on it

query {
  currentBulkOperation {
    status        # CREATED → RUNNING → COMPLETED (or FAILED / CANCELED)
    objectCount   # running total of records processed
    url           # the JSONL download link, once COMPLETED (expires in 7 days)
  }
}

Poll every few seconds — or subscribe to the bulk_operations/finish webhook so Shopify tells you when it's done instead of you asking.

3. What's in the box: JSONL + __parentId

The file is JSONL — "JSON Lines" — one record per line, not one big nested object. Here's the part everyone forgets: the box is loose. An order and its line items are not packed together. Each line item is its own line, with a sticky note — the __parentId field — saying which order it belongs to:

{"id":"gid://shopify/Order/1001","name":"#1001"}
{"id":"gid://shopify/LineItem/55","name":"Backpack","quantity":2,"__parentId":"gid://shopify/Order/1001"}
{"id":"gid://shopify/LineItem/56","name":"Bottle","quantity":1,"__parentId":"gid://shopify/Order/1001"}
{"id":"gid://shopify/Order/1002","name":"#1002"}

So you do the sorting: read each line and use __parentId to put line items back under their order. Shopify emits children right after their parent, so a common pattern is: hold the current parent, attach the child lines that follow, and flush when the next parent appears.

Stream it — don't load it all The file can be gigabytes. Never JSON.parse the whole thing — you'll run out of memory. Read one line, handle it, drop it. Memory stays flat no matter how big the store. This is the "export a million products" answer.

4. When to use it (and when not to)

Use a bulk operationUse a normal query
Export/import huge datasetsFetch one order by id
Initial full ERP/CRM importA small, quick read
Nightly "all products" jobLive request in a page
Avoiding the rate-limit bucketYou need the data instantly
Say it like this

"A bulk operation is an async job. I start it with bulkOperationRunQuery, poll currentBulkOperation (or use the finish webhook) until it's COMPLETED, then download a JSONL file from the url. The file is flattened — children like line items carry a __parentId, so I stream it line by line and re-group children under their parent. That keeps memory flat and avoids the rate-limit bucket, which is why it's right for large exports and the initial ERP sync."
