Checkout Extensibility

Why Shopify checkout is "painful" now: the old anything-goes editing is gone, and you can only customize it through a few locked-down doors. Knowing the limits is the senior signal.

Your win: answer "Why is Shopify checkout hard to customize now, and how do you do it?" — and sound like you have lived through the migration.

Ties to your mission: the client called checkout/payment "quite painful." This lesson explains why and gives you the map. It leans on L1 (APIs) and sets up L24 (Functions) and L25 (Plus).

1. The one idea: checkout is locked; you get a few doors

In the old world, you edited checkout.liquid and injected any Liquid or JavaScript you wanted — an anything-goes editor. That world is gone. Shopify replaced it with Checkout Extensibility — a set of fixed, sanctioned extension points. You can only change checkout through those doors. That restriction is exactly why it feels painful, and knowing the doors is what makes you sound senior.

The apartment picture Old checkout was a house you owned — knock down any wall you liked. New checkout is a rented apartment: you can hang pictures on the marked hooks (extension points) and repaint within the rules (branding), but you cannot move the plumbing. Most "why can't I just…" pain is someone trying to knock down a wall that is now load-bearing (part of the structure — it cannot be removed).

2. The deadlines that already passed (say these with confidence)

DateWhat was removed
Aug 13, 2024checkout.liquid stopped working for in-checkout pages (Information, Shipping, Payment)
Aug 28, 2025checkout.liquid, additional scripts, and script tags removed for the Thank-You and Order-Status pages

So today there is no Liquid checkout at all. Any store that did not migrate was moved to a plain out-of-the-box checkout. To be precise about plans: advanced / native checkout customization — the drag-and-drop checkout editor and custom-app Functions — is Plus-gated, but app-delivered UI extensions work on any plan (see L25).

3. The three doors (plus one for tracking)

1. Checkout UI extensions → change the INTERFACE (add fields, banners, offers) 2. Shopify Functions → change the BEHAVIOR (payment, delivery, discount logic) 3. Checkout Branding API → change the LOOK (colors, fonts, corners) + Web Pixel extensions → TRACK events (analytics, marketing)

Door 1 — Checkout UI extensions

Small components (built in React or JavaScript) that render at fixed targets — named slots like "below the shipping address" or "near the order summary." You cannot place them anywhere; only at the slots Shopify exposes.

The sandbox — this is the source of the pain Checkout UI extensions run in a sandboxed web worker, not on the main page. That means no direct DOM access — you cannot query or edit the page's HTML, and you cannot inject arbitrary scripts. You work only through Shopify's provided components and APIs. This sandbox is why so many "just add a bit of JS to checkout" requests are now impossible, and saying this out loud proves you understand the new model.

So a senior can answer "show me" on the spot. A minimal UI extension is a component bound to a named target, plus a shopify.extension.toml that declares that target:

// src/Checkout.jsx — render a banner at a fixed checkout target
import {reactExtension, Banner} from "@shopify/ui-extensions-react/checkout";

export default reactExtension("purchase.checkout.block.render", () => (
  <Banner title="Orders ship in 2 business days" />
));
# shopify.extension.toml — declares the extension and its target
api_version = "2025-07"

[[extensions]]
type = "ui_extension"
name = "ship-time-banner"

  [[extensions.targeting]]
  target = "purchase.checkout.block.render"
  module = "./src/Checkout.jsx"

The target string is the slot; you cannot invent one — you pick from the targets Shopify exposes.

Door 2 — Shopify Functions

Server-side logic that changes checkout behavior: custom discounts, and hiding/renaming/reordering payment and delivery methods. Functions replaced the old Shopify Scripts. This is big enough to get its own lesson — L24.

Door 3 — Checkout Branding API

Controls the look — colors, fonts, corner styles, logo — through the GraphQL Admin API (the checkoutBrandingUpsert mutation), not by editing a template. UI extensions automatically inherit these brand settings, so the whole checkout stays visually consistent.

Say it like this

"Checkout is painful now because Shopify locked it down. checkout.liquid is gone — removed for in-checkout pages in August 2024 and for the thank-you and order-status pages in August 2025 — so there's no Liquid checkout anymore. You customize only through Checkout Extensibility: UI extensions for the interface, which run sandboxed so there's no direct DOM access; Shopify Functions for behavior like payment and delivery customization; and the Checkout Branding API for styling. A lot of my job is knowing what's actually possible in those extension points and steering clients away from requests that used to be easy but aren't anymore."
