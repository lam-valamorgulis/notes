Order-Allocation Fairness Scorer

The Ship-from-Store brain: given an order and many candidate stores, pick the best store(s) to fulfil it — balancing stock, distance, and fair load, preferring one shipment.

Do this first: cover the model answer. 25-minute timer. Clarify, plan, then type it from blank while narrating the scoring trade-offs. Maps to Lesson 6.

The prompt

Task "Write allocate(order, candidateStores) that returns which store fulfils which line items. Prefer a single store that can ship the whole order; split across the fewest stores only when needed. Balance stock coverage, proximity to the customer, and fair load."

Step 1 — Clarify out loud

  • "'Nearest with stock' is the trap — it overloads one store and ignores capacity. I score candidates on several factors."
  • "Objective in priority order: fulfil the order, then minimise shipments, then minimise cost and balance load."
  • "Fairness = capacity-aware: a store near its daily cap scores lower, so work spreads."
  • "If one store covers everything, use it. If not, split across the fewest stores that cover the order."

Step 2 — Say the plan

1. Score each candidate: W_cov*coverage + W_prox*proximity + W_fair*capacity (+ rules). 2. If the top store covers ALL lines -> allocate everything there (one shipment). 3. Else greedily: take the best store, allocate the lines it covers, then re-score the rest for the remaining lines. Repeat until covered. 4. If lines remain uncovered -> warehouse fallback / partial + notify.

Step 3 — Build it (open your editor)

The traps this kata tests

TrapWhy it fails
Greedy "nearest with stock"Overloads the flagship store, ignores capacity, and splits needlessly. Score, don't grab.
Ignoring shipment countTwo nearby stores can cost more (two parcels) than one slightly-farther store. Prefer fewer shipments.
No fairness termThe closest store gets every order and its staff drown while others idle. Capacity must lower the score.
Assuming a store covers the whole orderIt may hold 2 of 3 lines. Handle the split — allocate what it covers, re-score for the rest.
No terminal caseIf no store (and no warehouse) can cover a line, you must fall back / partial-fulfil + notify, not loop.
"I score each candidate on coverage, proximity, and fairness/capacity rather than grabbing the nearest. The objective is priority-ordered: fulfil, then fewest shipments, then cost and balance. If one store covers the order it wins; otherwise I greedily take the best store, allocate what it covers, and re-score for the remainder — falling back to the warehouse if the network can't cover a line."

Say how you'd test it

  • One store covers all lines but is slightly farther than two that split → single store wins (fewer shipments).
  • A near store is at capacity → its score drops, work goes to the next store.
  • No single store has everything → split across the fewest that do.
  • A line no store carries → warehouse fallback (or partial + notify), no infinite loop.
