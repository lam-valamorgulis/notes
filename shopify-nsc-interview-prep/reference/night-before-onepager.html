Your 10 soundbites

One spoken line each. Say them out loud once. If they flow, close the laptop.

  1. Admin vs Storefront API: "Admin API is the server-side API to manage the store; Storefront API is the customer-facing GraphQL API for shopping experiences. Integrations use the Admin API."
  2. Rate limits: "GraphQL Admin uses calculated query cost — a 1000-point bucket refilling 50 a second. I watch the throttle status, request only what I need, and back off."
  3. Reliable webhook: "Verify HMAC on the raw body, return 200 in under five seconds, queue it, process idempotently, dedupe on the webhook id."
  4. App auth: "Session token from the embedded app, exchanged for an access token via token exchange — no redirects. Offline tokens for background jobs, online for a logged-in user."
  5. The ERP sync design: "Bulk import for the first load, webhooks for real-time changes into a queue and idempotent workers, and a reconciliation job to catch anything missed."
  6. No-lost-orders guarantee: "At-least-once delivery plus idempotent consumers, a durable queue with a dead-letter queue, and reconciliation against Shopify as the source of truth."
  7. Node event loop: "A single thread runs my JS with non-blocking I/O, so it handles thousands of connections. CPU-heavy work goes to worker threads or a queue."
  8. NestJS + DI: "Nest gives structure — modules, controllers, services — and dependency injection, which makes the code testable and loosely coupled."
  9. SQL vs NoSQL choice: "SQL for structured, related data that needs transactions, like orders. NoSQL for flexible shapes and simple high-scale reads. I choose by the data and the access pattern."
  10. Kafka vs SQS pick: "Kafka when I need a replayable, high-throughput log with many consumers. SQS when I want a simple managed queue with nothing to run."

Never forget

The six things that separate senior from junior
  • Verify HMAC on the raw body — before parsing.
  • Return 200 within 5 seconds; do the work after.
  • Make consumers idempotent — duplicates must be safe.
  • Back off on rate limits; watch the throttle status.
  • Always state the trade-off — what you chose and what you gave up.
  • Ask clarifying questions first — never design the wrong thing.
