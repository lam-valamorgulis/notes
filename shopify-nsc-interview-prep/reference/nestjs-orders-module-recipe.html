NestJS OrdersModule: Guard + DI + Unit Test

One realistic feature that ties three lessons together: a NestJS module that receives Shopify order webhooks, verifies them with a guard, and a unit test that injects a mock Shopify service.

Why this one example is worth studying: it shows NestJS DI & guards (L7), webhook HMAC (L2), and mock-injection testing (L14) working together — the exact shape of real NSC work.

The files

orders/ ├── orders.module.ts // wires the feature together ├── orders.controller.ts // the webhook route (guarded) ├── shopify-webhook.guard.ts // verifies HMAC before the handler runs ├── orders.service.ts // business logic — depends on ShopifyService ├── shopify.service.ts // calls the Shopify Admin API (mocked in tests) └── orders.service.spec.ts // unit test: injects a MOCK ShopifyService

1. The module — wiring by dependency injection

A module groups a feature. providers are the injectable classes; Nest builds them and hands them to whoever asks in a constructor.

orders.module.ts
import { Module } from '@nestjs/common';
import { OrdersController } from './orders.controller';
import { OrdersService } from './orders.service';
import { ShopifyService } from './shopify.service';

@Module({
  controllers: [OrdersController],
  providers: [OrdersService, ShopifyService],   // injectable classes
})
export class OrdersModule {}

2. The guard — verify the HMAC before the handler runs

A guard is a reusable gate that runs before the route handler. This one rejects any webhook whose HMAC does not match. Needs rawBody: true in main.ts (HMAC must hash the raw bytes — see the Webhook → ERP recipe).

shopify-webhook.guard.ts
import { CanActivate, ExecutionContext, Injectable, UnauthorizedException } from '@nestjs/common';
import * as crypto from 'crypto';

@Injectable()
export class ShopifyWebhookGuard implements CanActivate {
  canActivate(ctx: ExecutionContext): boolean {
    const req = ctx.switchToHttp().getRequest();
    const hmacHeader = req.headers['x-shopify-hmac-sha256'] as string;
    const rawBody: Buffer = req.rawBody;                 // requires rawBody: true in main.ts
    if (!hmacHeader || !rawBody) throw new UnauthorizedException();

    const digest = crypto
      .createHmac('sha256', process.env.SHOPIFY_API_SECRET)  // the client secret
      .update(rawBody)                                        // the RAW bytes
      .digest('base64');

    const ok = crypto.timingSafeEqual(Buffer.from(digest), Buffer.from(hmacHeader));
    if (!ok) throw new UnauthorizedException('invalid hmac');
    return true;                                             // pass → handler runs
  }
}

3. The controller — ack fast, hand off to the service

The controller injects OrdersService (DI), returns 200 quickly, and lets the service do the real work. The guard is attached with @UseGuards.

orders.controller.ts
import { Controller, Post, Req, UseGuards, HttpCode } from '@nestjs/common';
import { ShopifyWebhookGuard } from './shopify-webhook.guard';
import { OrdersService } from './orders.service';

@Controller('webhooks/shopify')
export class OrdersController {
  constructor(private readonly orders: OrdersService) {}   // DI: Nest injects OrdersService

  @Post('orders-create')
  @HttpCode(200)                     // ack fast, within Shopify's 5s window
  @UseGuards(ShopifyWebhookGuard)    // guard runs BEFORE this handler
  async handleOrderCreate(@Req() req) {
    const event = JSON.parse(req.rawBody.toString('utf8'));
    const webhookId = req.headers['x-shopify-webhook-id'];
    await this.orders.enqueue(webhookId, event);   // heavy work happens on a worker
  }
}

4. The services — one depends on the other

OrdersService holds business logic and depends on ShopifyService (which calls the real Admin API). Nest injects it through the constructor — and that is exactly what makes the test easy.

shopify.service.ts (the dependency we will mock)
import { Injectable } from '@nestjs/common';

@Injectable()
export class ShopifyService {
  // real GraphQL call to the Shopify Admin API. In tests we swap this for a fake.
  async getOrder(orderId: string): Promise<any> {
    // ...call Shopify Admin API, return the order...
  }
}
orders.service.ts
import { Injectable } from '@nestjs/common';
import { ShopifyService } from './shopify.service';

@Injectable()
export class OrdersService {
  constructor(private readonly shopify: ShopifyService) {}   // DI: injected dependency

  async enqueue(webhookId: string, event: any): Promise<void> {
    // (idempotency + queue omitted here — see the Webhook → ERP recipe)
  }

  // pure-ish logic that USES the dependency — the part we unit test
  async buildErpPayload(orderId: string) {
    const order = await this.shopify.getOrder(orderId);   // ← dependency call
    return {
      externalId: order.id,
      total: Number(order.total_price),
      lineCount: order.line_items.length,
    };
  }
}

5. The unit test — inject a MOCK ShopifyService

This is the payoff of dependency injection: in the test we replace the real ShopifyService with a fake, so no network call happens. We control what it returns and assert what OrdersService does with it.

orders.service.spec.ts
import { Test } from '@nestjs/testing';
import { OrdersService } from './orders.service';
import { ShopifyService } from './shopify.service';

describe('OrdersService', () => {
  let service: OrdersService;

  // a fake ShopifyService — no real Shopify call
  const mockShopify = { getOrder: jest.fn() };

  beforeEach(async () => {
    const moduleRef = await Test.createTestingModule({
      providers: [
        OrdersService,
        { provide: ShopifyService, useValue: mockShopify },   // ⭐ inject the MOCK
      ],
    }).compile();

    service = moduleRef.get(OrdersService);
    jest.clearAllMocks();
  });

  it('builds an ERP payload from a Shopify order', async () => {
    // arrange: the mock returns a fixture instead of calling Shopify
    mockShopify.getOrder.mockResolvedValue({
      id: 'gid://shopify/Order/1001',
      total_price: '129.90',
      line_items: [{ id: 1 }, { id: 2 }],
    });

    // act
    const payload = await service.buildErpPayload('gid://shopify/Order/1001');

    // assert
    expect(mockShopify.getOrder).toHaveBeenCalledWith('gid://shopify/Order/1001');
    expect(payload).toEqual({
      externalId: 'gid://shopify/Order/1001',
      total: 129.90,
      lineCount: 2,
    });
  });
});
Why DI makes this test trivial OrdersService never creates its own ShopifyService — it receives one. So the test hands it a fake via { provide: ShopifyService, useValue: mockShopify }. No network, fast, deterministic. That is the whole point of dependency injection: swap real for fake at the boundary.

Say-it checklist

  • Module groups the feature; providers are injectable; Nest wires them by constructor.
  • Guard runs before the handler — here it verifies the webhook HMAC on the raw body and rejects if it fails.
  • Controller returns 200 fast, hands the event to the service (which queues the heavy work).
  • OrdersService depends on ShopifyService via DI — so the unit test injects a mock and never hits the network.
  • Test shape: Test.createTestingModule → { provide, useValue } → arrange (mock returns a fixture) → act → assert.

Shopify facts verified against shopify.dev (2026-07-09): webhook HMAC = HMAC-SHA256 of the raw body with the app client secret vs the X-Shopify-Hmac-SHA256 header; respond 200 within ~5s; dedupe via X-Shopify-Webhook-Id.
