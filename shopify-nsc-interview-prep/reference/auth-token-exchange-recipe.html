App Auth: Session Token → Token Exchange

The three code pieces of modern embedded-app auth: App Bridge attaches the session token, your server verifies the JWT, then exchanges it for an access token.

Use this for: the app-auth deep-dive (L3). The one sentence that wins it: "session token authenticates browser→my backend; access token authenticates my backend→the Admin API."
Browser (embedded app + App Bridge) │ fetch('/api/...') → Authorization: Bearer <session-token JWT> ▼ Your backend │ 1. verify the session-token JWT (client secret, HS256, aud = your client id) │ 2. token exchange: session token → access token ▼ Shopify Admin API (call it with the access token)

1. App Bridge attaches the session token

Load App Bridge with your API key. Modern App Bridge patches fetch so relative-URL calls to your backend automatically carry the session token.

<meta name="shopify-api-key" content="%SHOPIFY_API_KEY%" />
<script src="https://cdn.shopify.com/shopifycloud/app-bridge.js"></script>
// App Bridge auto-adds  Authorization: Bearer <session token>  to relative-URL fetches:
const res = await fetch('/api/products');     // header attached for you

// Or get the token yourself (needed for absolute / external URLs):
const token = await shopify.idToken();
await fetch('https://my-app.example.com/api/products', {
  headers: { Authorization: `Bearer ${token}` },
});
Key point The session token is a short-lived JWT (about 1 minute). App Bridge mints a fresh one per request — you never store it.

2. Verify the session-token JWT on the server

The token arrives as Authorization: Bearer <jwt>. Verify the signature (HS256, signed with your client secret) and the claims.

const jwt = require('jsonwebtoken');

function verifySessionToken(req) {
  const token = (req.get('Authorization') || '').replace(/^Bearer /, '');

  // jwt.verify checks the signature + exp + nbf + audience for you:
  const payload = jwt.verify(token, process.env.SHOPIFY_API_SECRET, {
    algorithms: ['HS256'],
    audience: process.env.SHOPIFY_API_KEY,   // `aud` MUST equal your app's client id
  });

  const shop = new URL(payload.dest).host;   // `dest` = the shop this request is for
  return { shop, userId: payload.sub, token, payload };
}

3. Exchange the session token for an access token

The backend swaps the verified session token for an access token it can use on the Admin API — no redirects.

async function tokenExchange(shop, sessionToken, { online = false } = {}) {
  const res = await fetch(`https://${shop}/admin/oauth/access_token`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      client_id: process.env.SHOPIFY_API_KEY,
      client_secret: process.env.SHOPIFY_API_SECRET,
      grant_type: 'urn:ietf:params:oauth:grant-type:token-exchange',
      subject_token: sessionToken,                                  // the session-token JWT
      subject_token_type: 'urn:ietf:params:oauth:token-type:id_token',
      requested_token_type: online
        ? 'urn:shopify:params:oauth:token-type:online-access-token'
        : 'urn:shopify:params:oauth:token-type:offline-access-token',
    }),
  });
  if (!res.ok) throw new Error(`token exchange failed: ${res.status}`);
  return res.json();
  // online  → { access_token, scope, expires_in, associated_user, ... }
  // offline → { access_token, scope, ... }
}

Put it together

app.get('/api/products', async (req, res) => {
  const { shop, token } = verifySessionToken(req);                 // step 2
  const { access_token } = await tokenExchange(shop, token);       // step 3 (offline)
  // ...now call the Admin GraphQL API with access_token
});
Store the token Save the offline access token per shop (encrypted) and reuse it for Admin API calls + background jobs. Don't exchange on every request — cache it.

Say-it checklist

  • Session token = browser → backend auth. Short-lived JWT from App Bridge, sent as Authorization: Bearer.
  • Verify it: HS256 with the client secret, aud = your client id, check dest/exp.
  • Token exchange: POST to /admin/oauth/access_token with grant_type=…:token-exchange, subject_token = the session token.
  • Access token = backend → Admin API auth. Offline (long-lived) for jobs/webhooks; online (per user) for user actions.
  • The client secret does double duty: verify the JWT and authenticate the exchange. Server-side only.

Verified against shopify.dev (checked 2026-07-09): token-exchange endpoint POST /admin/oauth/access_token with grant_type=urn:ietf:params:oauth:grant-type:token-exchange, subject_token_type=urn:ietf:params:oauth:token-type:id_token, requested type …online-access-token/…offline-access-token; session-token JWT uses HS256 with claims iss, dest, aud, sub, exp, nbf, iat, jti, sid.
