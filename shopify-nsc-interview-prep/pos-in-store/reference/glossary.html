POS & In-Store Glossary

Every term used in this sub-course, in the words an interviewer will use them. Adhere to these definitions in every lesson — if a lesson needs a new term, it gets added here first.

How to use this card Read it once end to end, then use it as a lookup. The right column is the part that matters — it is the distinction that stops the term being vague.

The core distinction

TermPlain meaningThe distinction that matters
POS
Point of Sale		 The till system in a physical shop. Rings up a sale, takes payment, prints a receipt. A POS writes a transaction. A stock-lookup widget only reads. Most "POS integrations" on a theme are the latter.
Shopify POS Shopify's own till app, running on an iPad or phone, selling from the same catalogue and inventory as the website. Not an integration — a replacement. If Shopify POS is the till, there is no second system to sync with.
Stock visibility
a.k.a. Find in Store		 Showing the shopper which nearby shops have an item on the shelf. Read-only. No order exists yet, so nothing needs to be reserved or written back.
Click & Collect
a.k.a. BOPIS		 Buy Online, Pick up In Store. Pay on the website, collect from a shop. The order is Shopify's; the handover is the shop's. So the chosen store must survive checkout — see cart attribute.
Ship from Store A normal online order that is packed and posted by a shop instead of a warehouse. Invisible to the shopper. Entirely a routing and allocation problem for the back end.

The integration patterns

TermPlain meaningThe distinction that matters
Vendor drop-in
Pattern A		 The theme loads the vendor's JS bundle, hands it a config object and an empty container, and stops. The browser talks straight to the vendor API. Shopify records nothing, so the shopper's choice cannot reach fulfilment.
Theme-woven widget
Pattern B		 The theme serialises its own catalogue into the page for the widget, and implements callbacks to write data back. You own the bridge. More files to maintain, but the store choice can actually reach the order.
POS UI Extension
Pattern C		 Your code running inside the Shopify POS app. Written in TSX/JSX with Preact, configured in TOML, rendered via remote-dom. Runs on the till, not on the storefront. Requires a real Shopify app — a shopify.app.toml project, not a theme.
Extension target The named slot a POS extension renders into: pos.home.tile.render, pos.home.modal.render, pos.product-details.block.render, pos.cart.line-item-details.action.render. Same vocabulary as checkout extensibility — tiles, actions, blocks. Learn the shape once and it transfers.

The mechanics

TermPlain meaningThe distinction that matters
Cart attribute A key-value pair stored on the Shopify cart. Written with POST /cart/update.js under attributes. The bridge. Cart attributes are carried onto the order (order.attributes), so they cross checkout with no server-side code.
Private attribute A cart attribute whose key starts with __. Documented as not affecting page rendering, which improves caching. Easy to forget, strong signal when you remember it.
Cart token The identifier in the /cart.js response that names this cart. Not stable forever. Emptying or recreating a cart changes it — so storing it as a reference can leave a stale pointer.
Outlet / location / site A physical shop. Every vendor picks a different noun. Match the vendor's word in conversation. Shopify says location; Retail Express says outlet.
Identity mapping The lookup that connects a Shopify variant_id (or SKU, or barcode) to the POS system's own stock code. Ask who owns it. If the vendor owns it, recreating a variant silently breaks stock lookups and you cannot fix it.
inventory_quantity The exact number of units Shopify thinks are on hand for a variant. Available in Liquid. Rendering it publicly publishes real stock counts to anyone reading page source. Prefer the available boolean, or a bucket.

The three inventory mutations

MutationBehaviourRetry-safe?
inventorySetQuantitiesAbsolute — sets on_hand or availableYes. Prefer this.
inventoryAdjustQuantitiesRelative — applies a deltaNo. A retry corrupts the count.
inventoryMoveQuantitiesMoves units between statesIt is a transfer — treat like a delta.

POS tiers — what the money buys

From help.shopify.com · POS Lite vs POS Pro. Taught in Lesson 4.

TermPlain meaningThe distinction that matters
POS LiteIncluded with paid Shopify plans.Multi-location inventory is in here. Several shops work fine on Lite — the tier gates workflows, not the data model.
POS ProCosts extra, per location.Gates "pickup in store", stock transfers, retail staff permissions, exchanges. Six shops means six licences.
Smart gridThe POS home screen of tiles.Where a pos.home.tile.render extension appears.

Systems you may hear named

NameWhat it is
Retail ExpressAn Australian retail POS and inventory platform. Offers a Click & Collect widget that queries stock per outlet using Shopify variant IDs.
stockinstoreAn Australian omnichannel SaaS — Find in Store, Store Locator, Click & Collect, Ship from Store — that sits between an ecommerce platform and physical store stock. Covered in depth in the sibling stockinstore sub-course.
ERPEnterprise Resource Planning — the back-office system for stock, purchasing, production, and finance. Often the real source of truth behind the POS.
Parallel runA migration technique: run the old and new systems side by side, compare their numbers, and only cut over once they agree. The standard answer to "how do you migrate a POS without losing stock accuracy?"
