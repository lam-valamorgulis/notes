Glossary

Every term used in this sub-course, each with the one distinction that stops it being vague. All nine lessons follow these definitions — if a lesson and this page ever disagree, this page is wrong and should be fixed.

The job itself

TermDefinitionThe distinction that matters
MigrationA one-time move of records from another system into Shopify, after which the source is switched off.It ends. That is why you may freeze the source.
Sync / integrationAn ongoing two-way flow between two systems that both stay alive.It never ends, so it needs conflict rules and monitoring forever. Not this sub-course — see main-course Lesson 11.
ReplatformA migration where the whole shop moves, not just the data — theme, apps, domain, payments.The data migration is one workstream inside it, usually not the largest.
FreezeThe moment the source system stops accepting edits and orders.The one advantage a migration has over a sync. Announce the exact minute.
CutoverThe window in which the store becomes live: delta pass, inventory, redirects, DNS.Should move minutes of data, not months. Everything else was loaded earlier.
Delta passThe re-run that picks up everything changed since the snapshot.Should be the same importer with a narrower query — not a second codebase.
Dry runRunning the importer against a development store before it counts.Its real purpose is testing identity, not data. Run identical input twice.
Reconciliation reportCounts and money totals on both sides, with every difference explained.The actual deliverable. Not a documented Shopify process — engineering practice.
LedgerYour own table with one row per source record: source ID, Shopify ID, status, error, run ID.Four jobs in one table: resume, retry queue, reconciliation, audit trail.

Identity

TermDefinitionThe distinction that matters
Matching keyThe field that answers "which Shopify record did this source record become?"The single most important decision in a migration. Decide it in hour one.
IdempotentAn operation you can repeat with no extra effect.Setting is idempotent; adding is not. Creating is not — unless you can look up first.
UpsertUpdate if it exists, create if it does not, in one call.productSet is one; productUpdate is not — it never creates.
Custom IDA unique metafield value that identifies a record across systems. Uses the id metafield type, which is automatically unique.Shopify's own documented answer to the matching-key problem. Lookup covers products, variants, collections, customers, orders, locations; create-or-update covers products and customers only.
HandleA record's URL slug. The match column in a product CSV import.Unique per store but not stable — it changes with the title. Fine for one shot, weak long-term.
SKUThe merchant's own stock code on a variant.Uniqueness is not enforced anywhere. Count blanks and duplicates before trusting it.
Reference metafieldA metafield whose value is another record's ID (product, variant, file, metaobject).Cannot be written until its target exists — which is why a store-to-store move is two passes.

Product shape

TermDefinitionThe number
OptionAn axis a buyer must choose to buy — size, colour, condition.Maximum 3 per product. Extras are dropped silently on import.
VariantOne purchasable combination of the option values.2,048 per product, raised from 100 in October 2025.
MediaImages, videos and 3D models attached to a product.250 items per product, unchanged by the variant count. Images: 20 MB, 4472 × 4472 px.
MetafieldExtra structured data on a record — filterable and displayable, never a purchase choice.metafieldsSet writes 25 per call, payload under 10 MB.
MetaobjectA standalone custom record other records can reference.Its definition must exist before entries can be created or referenced.
Daily variant throttleA cap on how many new variants a store may create per day.Shopify Plus is exempt. The two doc pages disagree on the threshold — 50,000 variants → 1,000/day, or 500,000 → 10,000/day. Measure on the real store.

Routes in

TermDefinitionThe limit
CSV importA file uploaded through the admin. No code, no app.15 MB, UTF-8, Handle is the key, and it cannot be cancelled once it begins.
Bulk operationA JSONL file handed to Shopify to process asynchronously.100 MB, 24 hours, 5 concurrent per shop per app from API version 2026-01, one connection field.
JSONLOne JSON object per line. "Each line in the JSONL file represents one input unit."Not an array. One line, one record.
Staged uploadstagedUploadsCreate gives you an authenticated URL to POST a file to.The file parameter must be the last parameter in the POST.
Offline tokenA long-lived app credential not tied to a user session.orderCreate is "only accessible to apps authenticated using offline tokens".

Orders and money

TermDefinitionThe default that bites
processedAtWhen the order was processed. "The date that appears on your orders and that's used in the analytic reports."Omit it and the whole history is dated to the import day.
Line-item priceWhat the customer actually paid for that line.Omit it and "the API populates the price automatically based on the variant price" — today's price on an old order. The money bug.
financialStatusPaid, pending, refunded, and so on."If not specified, then this will be derived through the given transactions." Send transactions and let it derive.
fulfillmentStatusWhether the order has shipped."Will default to unfulfilled if not included" — a fake backlog of every historical order.
Order notificationsStaff emails on each new order.On by default. One email per imported order, per staff member. Switch off first, back on after.
PANPrimary Account Number — the actual card number.Moving PANs needs Plus or Enterprise plus Shopify Professional Services. Tokens work on any plan.

Inventory and go-live

TermDefinitionThe distinction that matters
inventorySetQuantitiesWrites an absolute inventory number.Retry-safe. name accepts only available or on_hand; reason is required.
compareQuantityCompare-and-set: "will only update the quantity if the persisted quantity matches".A mismatch returns an error rather than overwriting. Use it when a sync may already be running.
referenceDocumentUriA URI "identifying the source system and document that caused this adjustment".Free audit trail. Put your migration run ID in it.
URL redirectAn old path mapped to a new one, so old links still work.Bulk route: stagedUploadsCreate → urlRedirectImportCreate → urlRedirectImportSubmit. Needs write_online_store_navigation. Must be live before DNS moves.
PublishingMaking a product available to a sales channel.Imported hidden products "aren't published until you make them available to your sales channels". Verify on the storefront, not the admin.
RollbackWhat you do when the migration is wrong.DNS, not data. Keep the old platform alive and paid for an agreed window.
