The What-Moves Matrix

One page to take into a scoping call. Every record type, its route in, and the catch. Read the "never moves" block out loud to the client before the work starts — that is the whole purpose of this page.

How to use it: go down the table with the client and mark each row in scope or out. Then send the "never moves" block as a written note. A loss agreed in week one is a decision; the same loss found at go-live is a complaint.

2. Moves with loss

RecordRouteWhat is lost or reshapedIn scope?
Customer recordsCSV · Customer API Passwords do not come. Customer CSV has no mapping support — headings must match Shopify's exactly.
Historical ordersApps or API only — Order API + Transaction API No CSV import exists. Each imported order emails every notified staff member. Multiple and automatic discounts are not supported.
Gift cards & store creditgiftCardCreate You move the balance, not the ledger behind it. Supply the original code or physical cards stop working.
Saved payment methodsShopify-assisted migration Stripe credit cards; Braintree credit cards and Apple Pay. PayPal and Google Pay not supported. Raw card numbers need Plus or Enterprise plus Professional Services.
Products with 4+ option axesAny route The extra axis is dropped silently. Fold two axes into one, or split into separate products. Client's decision.

3. Never moves — read this block to the client

RecordWhyWhat you do instead
Customer passwords The old system holds one-way hashes. Nobody knows the passwords, including them. Passwordless sign-in — email plus a one-time 6-digit code — plus one clear customer email on launch day.
Product reviews They live inside a review app or the old platform. "You can't export or migrate reviews from WooCommerce to Shopify." Budget a review app and use its own import path. Expect a re-collection period.
Analytics & report history No documented route. The old dashboards die with the old platform. Export the reports the client cares about as files before the contract ends. Your reconciliation report becomes the archive.
Discount code usage history Codes can be recreated; how many times each was redeemed is not order data. Recreate active codes only. Agree that usage caps restart.
App configuration and data Each app keyed its data to the old store's IDs. Reinstall and reconfigure. Treat every app as a separate small project.

4. The three scoping questions

QuestionWhy it is worth asking first
Is the old system being switched off?"No" means this is a sync, not a migration. Different design, different price.
How far back do orders go?Shopify suggests the return-policy window as the minimum, 2–5 years as normal. Halving the window can halve the project.
Which Shopify plan is the store on?Non-Plus stores have a daily throttle on creating new variants. Plus is exempt. On a large catalogue this decides whether a date is achievable.
Two things to count before giving an estimate 1. Distinct option names in the source catalogue — one GROUP BY tells you whether you have a 3-option problem. 2. Duplicate and blank SKUs — one GROUP BY … HAVING COUNT(*) > 1 tells you whether the SKU is usable as a key. Both take two minutes and both save a week.

Every documented figure and quote on this page was read on 2026-08-03 from help.shopify.com and shopify.dev — see the source list on the glossary. The "analytics history" and "app configuration" rows describe the absence of a documented route rather than a stated limit, and are marked as such in Lesson 2.
