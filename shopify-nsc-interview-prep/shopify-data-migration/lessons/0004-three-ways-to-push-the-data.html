Lesson 4 · Shopify Data Migration · The pipes

Three Ways to Push the Data

CSV import, one mutation per record, or a bulk operation. Choosing between them is not a taste question — four published numbers decide it, and each route has a trap the docs state plainly and nobody reads.

Your win today: pick a route in under a minute using the real limits — 15 MB, 100 MB, 5 concurrent, 24 hours — and name the CSV trap that changes variant IDs and breaks other systems.

Ties to your mission: main-course Lesson 18 already teaches how a bulk operation works. This lesson does not repeat it — it teaches which route to choose, and what each one costs you.

1. The three routes

THREE WAYS IN ┌─ A · CSV IMPORT ──────────────────────────────────────────┐ │ file → Shopify admin → done │ │ no code, no app, no credentials │ │ 15 MB cap · Handle is the key · CANNOT be cancelled │ └───────────────────────────────────────────────────────────┘ ┌─ B · ONE MUTATION PER RECORD ─────────────────────────────┐ │ your code → Admin GraphQL → per-record response │ │ full control, per-record error handling, easy to resume │ │ paced by the cost-based rate limit │ └───────────────────────────────────────────────────────────┘ ┌─ C · BULK OPERATION ──────────────────────────────────────┐ │ JSONL → staged upload → bulkOperationRunMutation → poll │ │ hand a file to Shopify and walk away │ │ 100 MB · 24 h · 5 at once per shop per app │ └───────────────────────────────────────────────────────────┘ A is fastest to START. C is fastest to FINISH. B is the only one that tells you which record failed and why.

2. Route A — the CSV import

It is genuinely the right answer sometimes. A 3,000-product catalogue with clean data does not need an app. But the rules are strict and three of them are traps.

RuleDocumented asConsequence
Size"Your product CSV can't exceed 15 MB."Split the file. Splitting mid-product breaks variants — split on product boundaries.
EncodingUTF-8 requiredAn export opened and saved in Excel on a Windows machine is a classic source of broken accents.
Match keyThe Handle column, with "Overwrite products with matching handles"Your only idempotency mechanism on this route — see Lesson 3.
Blank vs omittedBlank non-required columns overwrite existing data as blank; omitted columns are left unchangedNever ship a "cleaned up" file with empty columns. Delete the column instead of emptying it.
No undo"Product imports started with a CSV file can't be canceled once they begin"A wrong 15 MB file runs to completion. Test on a development store, every time.

All quotes from help.shopify.com · Importing products with a CSV file, read 2026-08-03.

Trap 1 — the spreadsheet eats your images Documented: "Importing a CSV file that has been sorted by a spreadsheet editor such as Microsoft Excel or Apple Numbers might cause your products to be removed from their relevant image links on the CSV, and your product's images will be lost."

The cause is structural. A product with three images is three rows, and only the first carries the title and handle. Sort the file and those rows scatter, so the image rows no longer sit under their product. Edit product CSVs with a script or a text editor — not by clicking a column header.
Trap 2 — changing an option renumbers your variants Documented: changing Option values "deletes existing variant IDs, and creates new variant IDs. Any change to variant IDs values can break third-party dependencies."

So a tidy-up pass — renaming the option "Colour" to "Color" — silently replaces every variant ID on the store. Anything holding those IDs breaks at once: subscription contracts, a warehouse system, a marketplace feed, an analytics history. This is the single most expensive innocent-looking edit in Shopify.
Customer CSVs are stricter than product CSVs "You can't import a customer CSV that doesn't match the Shopify headings. There is no data mapping support for customer CSV imports." No mapping screen at all — the headings must match exactly. Budget a transform step rather than hoping the export lines up.

3. Route B — one mutation per record

The workhorse. Your code walks the source records and calls productSet, customerSet or orderCreate once each.

Its cost is speed: you are paced by Shopify's cost-based rate limit — a points bucket that refills over time, described in main-course Lesson 1. Its value is knowing exactly which record failed and why, which is worth more than throughput on a migration where every skipped record must be explained in the reconciliation report.

Why this is usually the right default A migration's hardest requirement is not speed — it is accounting. Route B gives you a per-record result you can store: source ID, Shopify ID, status, error text. That table is your reconciliation report from Lesson 1. Routes A and C make you reconstruct it afterwards from a results file.

4. Route C — the bulk operation

You write a JSONL file where "each line in the JSONL file represents one input unit", upload it to a staged URL, hand Shopify the mutation plus the file, and poll until it finishes. Five steps, covered in Lesson 18. What matters here are the limits, because they set your batch size:

LimitDocumented asHow it shapes the plan
File size"The size of the JSONL file can't exceed 100MB"About 6× a CSV import's cap. Chunk your source into 100 MB files at record boundaries.
Time"The bulk mutation operation has to complete within 24 hours"A single job cannot span a long weekend. Size chunks so each finishes in hours, not days.
Concurrency"In API versions 2026-01 and higher, each app can run up to five bulk mutation operations per shop simultaneously"Real parallelism — five in flight. On older versions, assume one.
Shape"The mutation that's passed into bulkOperationRunMutation is limited to one connection field"You cannot push products and their full media list in one deeply nested job. Split into passes.
Which mutations"You can supply any GraphQL Admin API mutation … except for bulkOperationRunMutation and bulkOperationRunQuery themselves"Wide open. The named examples are productCreate, collectionCreate, productUpdate, productUpdateMedia.

Quotes from shopify.dev · Bulk operation imports, read 2026-08-03.

One detail that wastes an afternoon When you POST the file to the staged URL: "The file parameter must be the last parameter in the list." Put it earlier and the upload fails in a way that does not obviously say why. Set resource: BULK_MUTATION_VARIABLES, mimeType: "text/jsonl", httpMethod: POST on stagedUploadsCreate.
Cover the screen Four numbers: the CSV cap, the JSONL cap, how many bulk mutations can run at once from 2026-01, and how long one has to finish.

5. Choosing, in under a minute

THE DECISION does the client just need it in, and is the data clean? │ ├── YES, and under ~15 MB, and no per-record report needed │ → A · CSV IMPORT (an hour, no code) │ └── NO │ ├── do I owe a per-record explanation for every skip? │ (almost always YES on a paid migration) │ → B · MUTATION PER RECORD │ └── is the volume big enough that pacing is the problem, and can I reconcile from a results file afterwards? → C · BULK OPERATION (or B for the accounting, C for the bulk fields) ⇒ the honest professional answer is usually "B for correctness, C for the volume-heavy passes, and A never on a live store I care about."
Say it this way

"I would default to one mutation per record, because a migration's hardest requirement is accounting, not speed — I need a row per source record saying what happened to it, and that table becomes the reconciliation report. I would reach for bulk operations on the volume-heavy passes where pacing is the real constraint, and accept reconciling from the results file. CSV import I would use for a small clean catalogue or a one-off, never on a live store, because the import cannot be cancelled once it starts."

Remember this
  • Three routes: CSV import, one mutation per record, bulk operation. A starts fastest, C finishes fastest, B is the only one that reports per record.
  • CSV: 15 MB, UTF-8, Handle is the key, and an import cannot be cancelled once it begins.
  • Blank columns overwrite; omitted columns do not. Delete a column, never empty it.
  • Sorting a product CSV in Excel or Numbers can lose your images — extra image rows separate from their product.
  • Changing an Option value deletes and recreates variant IDs, breaking anything that stored them.
  • Customer CSVs have no mapping support — headings must match Shopify's exactly.
  • Bulk: 100 MB JSONL, 24 hours, five concurrent per shop per app from 2026-01, one connection field, and the file parameter must be uploaded last.
  • Default to B for accounting, C for volume, A almost never on a live store.
If you remember one thing: pick the route by what you owe the client — if you owe an explanation for every missing record, you owe yourself a per-record response.
