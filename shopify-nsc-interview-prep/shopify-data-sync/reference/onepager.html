The One-Pager

Everything compressed. Read this in the hour before the call, out loud, once. Do not open anything else — at this point more reading makes you slower, not better.

If you only hold one sentence: there is one pile of cards and two counters of it. Everything you build is a decision about which count is allowed to win, how fast the loser finds out, and what you say to the customer when the answer arrives too late.

The five facts

FactThe number or phrase
Where a quantity livesInventoryLevel = InventoryItem × Location. Not on the variant. Eight states, one of which is safety_stock
What a cart promisesNothing. No check, no hold. The only guarantee is at payment
Webhook retries8 times over ~4 hours, then the subscription is deleted — stated for subscriptions configured via the Admin API
Ordering guaranteeNone. "Shopify doesn't guarantee ordering within a topic, or across different topics for the same resource"
Rate limit scopePer app-and-store pair. Standard 100 points/sec · Advanced 200 · Plus 1000 · enterprise 2000. Single query max 1000

The four pieces you would build

1. A CHANGE LOG so every push is replayable, ordered by VERSION not by clock 2. A PUSH WORKER absolute writes, + compareQuantity + origin stamped on every write a rejection triggers a RE-READ 3. A WEBHOOK RECEIVER verify HMAC · dedupe on webhook id · enqueue · 200. Nothing else. The worker is idempotent on order id, key written FIRST 4. A RECONCILER nightly bulk read-back classify: pending message = LAG heal the explainable ALARM on the unexplainable

The six sentences to say

WhenSay
Opening any sync conversation"Before I design anything I want to name, per field, which system owns it. Sync is cheap with one owner and one direction."
Explaining the oversell"Shopify is not wrong, it is stale. Those are different faults with different fixes."
On compareQuantity"It is a stop sign, not a fix. The re-read is what finds the truth."
On reconciliation"Heal the explainable, alarm on the unexplainable."
When both systems agree"Agreement is not correctness. After an oversell both sides say zero."
Closing a design answer"And the lag is a number the merchant agreed to, in writing, before it was a complaint."

The lesson-by-lesson trigger list

One line each. If any line does not immediately unpack into a paragraph in your head, that is the lesson to reopen — and only that one.

L01The page reports the last thing Shopify was told, not reality.
L02145 million catalogue cards versus 12,000 in the box. Four arrows one-way, quantity two-way.
L03Overwrite money, respect craft, alarm when unsure. last_pushed detects a human edit.
L04Replay is a Tuesday. Absolute writes make it boring.
L05Five ways to say gone. The sync never deletes. An empty read is a failed read.
L06Never compare one system's clock to another's. Version numbers, not timestamps.
L07A webhook is a hint. No fast path can detect its own silence.
L08More workers do not help. Collapse states, never events.
L09Pending message = lag, not drift. The unfulfillable report is the only detector.
L10Shopify isolated the tenants; we un-isolated them. FIFO rewards volume.
L11The lag is a promise and somebody has to sign it.

The three traps in the room

They offerYou say
"Real-time, two-way, both systems always current."Not achievable across two systems. Name the lag, design the reconciliation.
"Just shorten the interval."Makes it rarer, never impossible. The fix belongs at the promise, not the interval.
"Latest write wins."Two clocks. Works in testing, fails inside one second on the busy day.
The 90-second version for a non-technical person

"Your shop has two tills — the counter and the website. They cannot both know something at the same instant, so there is always a short gap. A counter sale leaves the website in a few seconds. Prices update overnight. On a big release day the gap can be minutes, and that is the day it matters — so on those days I would like to hold the last copy of your expensive cards back. And if we ever sell one twice, you will hear it from us before you hear it from the customer."
