The Ownership Matrix

One page to fill in before any sync is designed. It is deliberately blank — the value is in making somebody answer each row out loud, in a meeting, with their name against it.

The rule this page enforces: no field gets built until it has an owner, a direction and a rule for when a human edits it. A row you cannot fill in is not a small gap. It is the row that will produce the bug nobody can fix, because both systems will be behaving correctly.

How to fill each column

ColumnWhat goes in it
OwnerThe one system allowed to be right. Not "both". If the honest answer is both, write CONTESTED and it goes on the register below.
DirectionAn arrow. One-way is cheap; two-way is the whole cost of the project.
Rule on human editOverwrite, Respect after first edit, or Alarm. Decide by the cost of being wrong: overwrite money, respect craft, alarm when unsure. See L03.
If it is wrongThe consequence in plain words. "Cosmetic", "lost sale", "oversell", "a phone call". This is what sorts the priorities later.
Agreed byA person's name and a date. An unowned row is an unwritten promise.

The contested register

Every row you marked CONTESTED goes here. Keep this list short and defend its length. Each row multiplies the conflict cases you must reason about and test.

FieldWhy both sides write itAgreed rule when they collideHow we find out it collided
For reference — how Harbour City Cards filled it in Two rows. Quantity, because three doors draw on one box, resolved by absolute writes plus compareQuantity, found by the unfulfillable report. Tags, because the platform adds structural tags and the merchant adds merchandising ones, resolved as add-only, never remove. Everything else was made one-way on purpose.

The lag promise

The matrix says who wins. This says how fast the loser finds out. Fill it in with a number, not an adjective.

Fill in gap A and gap B separately, or the promise is meaningless The merchant only feels A + B — how long after a counter sale the website is right. But you probably only own B. If you promise a single combined number without knowing A, you have promised something that depends on a CSV somebody else uploads. Measure both, promise the one you control, and report the one you do not.
