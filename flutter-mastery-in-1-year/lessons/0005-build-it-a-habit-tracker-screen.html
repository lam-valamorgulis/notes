Month 1 · Lesson 5 · The real build

Build it — a habit tracker screen

Everything from Month 1 in one screen you would not be embarrassed to show someone: an immutable model, local state, derived stats, extracted widgets, a keyed list, and a controller that is properly disposed.

Your win today: a working app — add a habit, tick it off, swipe to delete, watch the progress bar move. And every line of it is a line you can explain.
Before you start You need flutter create habit_lab from Lesson 1. The Habit model is the one you wrote in Lesson 2 plus one new field: a stable id — you will see exactly why it has to be there when we get to keys. Everything below goes in a single lib/main.dart — one file on purpose, so you can see the whole shape at once. Month 6 is where we split a project into layers properly.

The plan — decompose before you type

Professionals do not start with code. They start by deciding what the state is and who owns it. Three questions, in order:

  1. What data does this screen need? A list of habits. Each habit has a title, whether it is done today, and a streak.
  2. What is real state, and what is derived? The list is state. "3 of 5 done" and the progress fraction are derived — computed from the list, never stored. (Lesson 2)
  3. Who owns the state? Only this screen cares, so it is ephemeral state — a StatefulWidget with setState. No library needed. (Lesson 3)

That gives the widget tree. Notice how few widgets need to be stateful:

Build it for real — the whole file

Type this, do not paste it. Typing is slower and that is the point — you will notice things you would otherwise skim past.

import 'package:flutter/material.dart';

void main() => runApp(const HabitLabApp());

// ─── MODEL ────────────────────────────────────────────────────────────
// Immutable: every field final, const constructor, copyWith to "change" it.
@immutable
class Habit {
  const Habit({
    required this.id,
    required this.title,
    this.done = false,
    this.streak = 0,
  });

  final int id;          // stable identity — this is what keys will use
  final String title;
  final bool done;
  final int streak;

  bool get isStrong => streak >= 7;   // derived, never stored

  Habit copyWith({String? title, bool? done, int? streak}) => Habit(
        id: id,
        title: title ?? this.title,
        done: done ?? this.done,
        streak: streak ?? this.streak,
      );
}

// ─── APP ──────────────────────────────────────────────────────────────
class HabitLabApp extends StatelessWidget {
  const HabitLabApp({super.key});

  @override
  Widget build(BuildContext context) {
    return MaterialApp(
      title: 'Habit Lab',
      debugShowCheckedModeBanner: false,
      theme: ThemeData(colorSchemeSeed: Colors.indigo),  // Material 3 palette from one colour
      home: const HabitHomePage(),
    );
  }
}

// ─── THE ONE STATEFUL WIDGET ──────────────────────────────────────────
class HabitHomePage extends StatefulWidget {
  const HabitHomePage({super.key});

  @override
  State<HabitHomePage> createState() => _HabitHomePageState();
}

class _HabitHomePageState extends State<HabitHomePage> {
  final _controller = TextEditingController();   // must be disposed!
  int _nextId = 3;

  List<Habit> _habits = const [
    Habit(id: 0, title: 'Drink water', streak: 9),
    Habit(id: 1, title: 'Read 20 pages', done: true, streak: 3),
    Habit(id: 2, title: 'Walk outside', streak: 7),
  ];

  // DERIVED values — computed on every build, never stored in a field.
  int get _doneCount => _habits.where((h) => h.done).length;
  double get _progress => _habits.isEmpty ? 0 : _doneCount / _habits.length;

  void _addHabit() {
    final title = _controller.text.trim();
    if (title.isEmpty) return;                   // guard first, then act
    setState(() {
      _habits = [..._habits, Habit(id: _nextId++, title: title)];  // NEW list
      _controller.clear();
    });
  }

  void _toggle(int id) {
    setState(() {
      _habits = [
        for (final h in _habits)
          if (h.id == id) h.copyWith(done: !h.done) else h,        // replace one
      ];
    });
  }

  void _remove(int id) {
    setState(() => _habits = _habits.where((h) => h.id != id).toList());
  }

  @override
  void dispose() {
    _controller.dispose();     // mirror of the field above. Never skip this.
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      appBar: AppBar(title: const Text('Habit Lab')),
      body: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            StatsHeader(
              doneCount: _doneCount,
              total: _habits.length,
              progress: _progress,
            ),
            const SizedBox(height: 16),
            _AddHabitField(controller: _controller, onSubmit: _addHabit),
            const SizedBox(height: 8),
            Expanded(                            // bounded height for the list — Lesson 4
              child: _habits.isEmpty
                  ? const Center(child: Text('No habits yet. Add one above.'))
                  : ListView.builder(            // lazy: builds visible rows only
                      itemCount: _habits.length,
                      itemBuilder: (context, index) {
                        final habit = _habits[index];
                        return Dismissible(
                          key: ValueKey(habit.id),   // identity, NOT the index
                          direction: DismissDirection.endToStart,
                          background: const ColoredBox(color: Color(0x22FF0000)),
                          onDismissed: (_) => _remove(habit.id),
                          child: HabitTile(
                            habit: habit,
                            onTap: () => _toggle(habit.id),
                          ),
                        );
                      },
                    ),
            ),
          ],
        ),
      ),
    );
  }
}

// ─── EXTRACTED WIDGETS (all stateless) ────────────────────────────────
class StatsHeader extends StatelessWidget {
  const StatsHeader({
    super.key,
    required this.doneCount,
    required this.total,
    required this.progress,
  });

  final int doneCount;
  final int total;
  final double progress;

  @override
  Widget build(BuildContext context) {
    final theme = Theme.of(context);              // context = ask my ancestors
    return Card(
      child: Padding(
        padding: const EdgeInsets.all(16),
        child: Column(
          crossAxisAlignment: CrossAxisAlignment.start,
          children: [
            Row(
              children: [
                Expanded(                          // take the space that's left
                  child: Text('Today', style: theme.textTheme.titleMedium),
                ),
                Text(
                  '$doneCount of $total done',
                  style: TextStyle(color: theme.colorScheme.primary),
                ),
              ],
            ),
            const SizedBox(height: 12),
            ClipRRect(
              borderRadius: BorderRadius.circular(999),
              child: LinearProgressIndicator(value: progress, minHeight: 8),
            ),
          ],
        ),
      ),
    );
  }
}

class _AddHabitField extends StatelessWidget {
  const _AddHabitField({required this.controller, required this.onSubmit});

  final TextEditingController controller;
  final VoidCallback onSubmit;

  @override
  Widget build(BuildContext context) {
    return Row(
      children: [
        Expanded(
          child: TextField(
            controller: controller,
            textInputAction: TextInputAction.done,
            onSubmitted: (_) => onSubmit(),        // keyboard "done" also adds
            decoration: const InputDecoration(
              hintText: 'New habit…',
              border: OutlineInputBorder(),
              isDense: true,
            ),
          ),
        ),
        const SizedBox(width: 8),
        IconButton.filled(onPressed: onSubmit, icon: const Icon(Icons.add)),
      ],
    );
  }
}

class HabitTile extends StatelessWidget {
  const HabitTile({super.key, required this.habit, required this.onTap});

  final Habit habit;
  final VoidCallback onTap;

  @override
  Widget build(BuildContext context) {
    final scheme = Theme.of(context).colorScheme;
    return Card(
      margin: const EdgeInsets.symmetric(vertical: 4),
      child: ListTile(
        onTap: onTap,
        leading: Icon(
          habit.done ? Icons.check_circle : Icons.circle_outlined,
          color: habit.done ? scheme.primary : scheme.outline,
        ),
        title: Text(
          habit.title,
          maxLines: 1,
          overflow: TextOverflow.ellipsis,          // never overflow — Lesson 4
          style: TextStyle(
            decoration: habit.done ? TextDecoration.lineThrough : null,
          ),
        ),
        trailing: habit.isStrong
            ? Chip(
                label: Text('${habit.streak}🔥'),
                visualDensity: VisualDensity.compact,
              )
            : Text('${habit.streak}d', style: TextStyle(color: scheme.outline)),
      ),
    );
  }
}

Run it with flutter run. Add a habit. Tap one. Swipe one away. Then change a colour and press r — the list keeps its state while the style updates. That is hot reload doing exactly what Lesson 1 described.

The walkthrough — every Month 1 idea, mapped

In the codeThe idea behind it
@immutable class Habit with final fields + copyWithImmutable model. You never edit a habit — you replace it. (L2)
bool get isStrong, int get _doneCountDerive, do not store. A computed value can never disagree with the list. (L2)
One StatefulWidget; everything else statelessEphemeral state, owned at the lowest common ancestor. Data down, events up. (L3)
_habits = [..._habits, newHabit]A new list, not .add(). It costs nothing here and it is the habit that makes Riverpod and BLoC work correctly in Months 4–5.
for (…) if (…) h.copyWith(…) else hcollection-for plus collection-if — replace one item immutably in one expression. (L2)
_controller.dispose()Mirror initState/field creation in dispose. A leaked controller is a real bug. (L3)
Expanded(child: ListView.builder(…))The list needs a bounded height inside a Column. .builder builds only visible rows. (L4)
key: ValueKey(habit.id)Identity, so Flutter matches the right element when items move or are removed. (L1, L3)
Expanded around the title TextPrevents a RenderFlex overflow when a name is long. (L4)
Theme.of(context)BuildContext is your address in the tree; .of looks upward for inherited data. (L1)
const on every fixed widgetA const widget is built once and reused, so Flutter can skip it on rebuild. (L2)
The mistake almost everyone makes here Writing setState(() => _habits.add(newHabit)); instead of building a new list. It appears to work, because setState rebuilds regardless. But you have now mutated an object that other code may be holding a reference to, and the moment you move to Riverpod or BLoC — which decide whether to rebuild by comparing old state to new — the same code will silently stop updating the screen. Build the immutable habit now, in Month 1, while the stakes are low.
Why extract HabitTile as a class, not a _buildTile() method? A method returning a widget is inlined into the parent's build, so it rebuilds every single time the parent rebuilds, and it can never be const. A separate class gets its own element in the tree, so Flutter can skip rebuilding it when its inputs have not changed — and it can be tested and reused on its own. This is a small decision with a large payoff in Month 8.

Extend it — three reps to make it yours

  1. Empty and edge states. Show a friendly message when the list is empty (already stubbed in), and stop the user adding a duplicate title. Where does that check belong — in the widget or the model?
  2. An "all done" celebration. When _progress == 1, change the header. Do it without adding a new state field — the information is already there.
  3. Undo the delete. After a swipe, show a SnackBar with an Undo action that puts the habit back at the same index. This one is genuinely fiddly: you have to keep the removed habit and its position somewhere. Notice how the need for an "undo" makes you want a proper state layer — that feeling is exactly why Month 4 exists.

Practice: read the situation, pick the move

Scenario · a code review comment

A colleague reviews your file and says: "Use the item's index as the Dismissible key — it is simpler and it works." You run it and the app seems fine.

Before you answer, work out what test would prove them wrong. Then answer the first quiz question below.

Say it like an interviewer just asked

Interview prep · Lesson 5

This is the pattern of a real senior interview: they hand you a small screen like this one and ask you to justify your decisions. Every question below is about a choice, not a fact. Answer out loud, about 60–90 seconds each.

  1. Walk me through this screen. Where does state live, and why there?
  2. Why ValueKey(habit.id) and not the list index?
  3. Why build a new list instead of calling add on the existing one?
  4. How would you test this screen?
  5. This screen will grow to support sync, multiple devices, and a settings page. What changes?
Read the primary source Required reading now that you have built something: State management fundamentals and the Key API docs. Both will read completely differently now than they would have a week ago — that is what building first buys you.
Paste your finished file and ask me to review it as a senior colleague would — I will comment on naming, widget extraction, state placement, and the things an interviewer would poke at. That review is the single highest-value thing you can do to close Month 1.
Remember this
  • Decide the state before you type. What data, what is derived, who owns it. The widget tree falls out of those three answers.
  • One owner of truth. One stateful widget at the top; everything below is stateless, receiving data and reporting events.
  • Derive, never store. _doneCount and _progress are getters, so they cannot go stale.
  • Replace, never mutate. [..._habits, new] and copyWith — the discipline that makes Months 4–5 work.
  • Extract widgets as classes, not build methods. Classes get their own element, can be const, and can be skipped on rebuild.
  • Key by identity, not by index. ValueKey(habit.id) survives reordering and removal; an index does not.
  • Everything created must be disposed. The TextEditingController is the first of many.
  • A list inside a Column needs Expanded, and long text needs ellipsis. Both from the constraint rule.

If you remember one thing: the quality of a Flutter screen is decided before you write a widget — by where you put the state and what you refuse to store twice.
