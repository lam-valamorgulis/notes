# Mission: Senior Flutter Mobile Developer in 1 Year

## Why
Land a **senior Flutter developer role near the end of this year (target: mid-2027)** and be
able to **take paid contract / freelance mobile work** alongside it. That means two things at
once: pass a senior interview (explain the framework, design a mobile system, review other
people's code), and ship an app to both stores **on my own** — build it, test it, release it,
support it, and price the work honestly for a client.

## Success looks like
- I can build a real Flutter app from a design, on both iOS and Android, without copying tutorials.
- I can explain **how Flutter actually renders a frame** (widget → element → render object) out loud, under pressure.
- I can write and defend an app architecture: layers, repositories, dependency injection, error handling.
- I use **Riverpod** as my daily tool and can also read, write, and critique **BLoC** code (most job ads still ask for it).
- I can find and fix a real performance problem with DevTools and show before/after numbers.
- I can write unit, widget, and golden tests, and gate them in CI.
- I have shipped at least one app to the **App Store and Google Play** from an automated pipeline.
- I can talk to a native platform (platform channels / Pigeon) and publish my own package on pub.dev.
- I can run a mobile **system design** interview: offline sync, auth, caching, push notifications.
- I can scope, estimate, and quote a freelance mobile project and explain the tradeoffs to a non-technical client.

## Constraints
- **Start point: new to both Dart and Flutter** (July 2026). No prior mobile development.
- **15–20 hours per week.** Pacing is aggressive on purpose: bigger monthly builds, extra deep dives, more mock interviews.
- Working on macOS. Xcode command line tools are present; **Flutter SDK and Android Studio are not installed yet** (Lesson 1 fixes this).
- Interview preparation must live **inside every lesson**, not only at the end of the year.
- Explanations in plain English. Simple vocabulary. Real technical names kept exactly as they are.

## Out of scope
- Flutter for **web and desktop** as a primary target. Mentioned where it matters, not chased.
- Native-only development (writing a whole app in Swift or Kotlin). Only the interop I need.
- Backend engineering. I consume APIs and add a local database; I do not build the server.
- Game development, Flame, and heavy 3D or shader work beyond one animation deep dive.
