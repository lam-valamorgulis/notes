The 12-Month Plan

One page that holds the whole year. Four phases, twelve monthly modules, one real build each. Tick each skill when you can do it — not when you have read about it.

How to use this: The Map tells the story; this page tracks what to tick off. Each month has a real build (the use case), a few skills, and one live-coding / interview drill. Your ticks are saved in this browser automatically.

Progress: 0 / 0 skills ticked

Pacing at ~10 hrs/week Roughly: ~2 hrs on the lesson (first principles), ~1 hr reading the primary docs, and ~6–7 hrs building the real project and doing the drills. This course is build-first on purpose — you learn React's hard parts by hitting them in real code, then say them out loud until an interviewer can't shake you. Everything is written in TypeScript.

Phase 1 · Months 1–3 · The mental model & core

Build the React way of thinking: state, props, composition, and how the screen updates.

M1UI = f(state) — the render model

Objective: understand what React is, how JSX becomes UI, how state triggers a re-render, and how React updates the real screen.

Build: an interactive dashboard card — typed props, local state, an event handler, and a keyed list — set up with Vite + React + TypeScript.

Drill: Live-build a counter, then a keyed list; then explain "what is the Virtual DOM, and is React fast because of it?"

Primary: React docs — Describing the UI, Render and Commit, Rendering Lists. Lessons: 0001, 0002, 0003, 0004.

M2State, events & lists in depth

Objective: manage state that changes over time, handle user events, and share state between components.

Build: a filterable to-do / search list — add, edit, delete, complete, and filter items, with state lifted to a common parent.

Drill: Build a to-do list with add/toggle/delete/filter, live. Then: why must state updates be immutable?

Primary: React docs — Adding Interactivity, Sharing State Between Components, Updating Arrays in State. Lessons: 0007, 0008, 0009, 0010.

M3Thinking in React

Objective: turn a static design into a working app using React's own step-by-step method.

Build: the classic filterable product data table — from a mockup to a component tree with the right state in the right place.

Drill: Given a mockup, list the components and mark each value as state or derived — out loud. Then build it.

Primary: React docs — Thinking in React, Choosing the State Structure. Lessons: 0011, 0012, 0013, 0014.

Phase 2 · Months 4–6 · The hard core

The parts that trip everyone up: effects, refs and the DOM, context and re-renders.

M4Effects & the outside world

Objective: connect React to things outside React (network, subscriptions, timers) without bugs.

Build: a live search box — debounced input, fetch on change, results cached, and in-flight requests cancelled so a slow old response never overwrites a fresh one.

Drill: Build a debounced live search that cancels stale requests, live. Then: "why does my effect run twice, and why is that good?"

Primary: React docs — Synchronizing with Effects, You Might Not Need an Effect, Lifecycle of Reactive Effects. Lessons: 0015, 0016, 0017, 0018.

M5Refs, the DOM & timing

Objective: reach the real DOM when you must, hold values that don't trigger renders, and run timers correctly.

Build: a click-outside modal (focus trap + escape key) and a custom media player with play/pause and a seek bar driven by a ref.

Drill: Build a modal that closes on outside-click and Escape, live. Then: why can a setInterval inside a component log stale state?

Primary: React docs — Referencing Values with Refs, Manipulating the DOM with Refs, useRef, useLayoutEffect. Lessons: 0019, 0020, 0021, 0022.

M6Context, re-renders & custom hooks

Objective: share state widely without prop-drilling, understand what causes re-renders, and package logic into reusable hooks.

Build: a theme + auth app — global state via context and a reducer, tuned with memo/useMemo/useCallback so changing one thing doesn't re-render the whole tree.

Drill: "This app re-renders everything on every keystroke — fix it." Then: when does useMemo actually help, and when is it just noise?

Primary: React docs — Passing Data Deeply with Context, Reusing Logic with Custom Hooks, memo.

Phase 3 · Months 7–9 · Real applications

Turn components that work into an app that survives real users and real data.

M7Server state & data fetching

Objective: manage data that lives on a server — the single biggest source of real-app complexity.

Build: a CRUD app (this becomes the "spine" you harden all year) with TanStack Query: caching, background refetch, mutations, and optimistic updates.

Drill: Add an optimistic "like" that rolls back on error, live. Then: name three bugs you get from fetching in a raw useEffect.

Primary: TanStack Query docs; React docs — fetching data.

M8Routing & app architecture

Objective: build a multi-page app and keep it maintainable as it grows.

Build: a multi-page dashboard — nested routes, URL params, protected routes, and code-split routes loaded with lazy + Suspense.

Drill: Add a protected, lazy-loaded settings route, live. Then: what should live in the URL vs in component state?

Primary: React Router docs; React docs — lazy, Suspense.

M9Forms, accessibility & testing

Objective: build forms that don't fight you, work for everyone, and are proven correct by tests.

Build: a multi-step form (validation, error summary, keyboard + screen-reader support) with a full test suite.

Drill: Write a failing test for a form bug, then fix it — live. Then: why does Testing Library tell you to query by role/label, not by class?

Primary: React Testing Library, Vitest; ARIA Authoring Practices.

Phase 4 · Months 10–12 · Modern React & the interview

Reach the frontier — Server Components — then be able to explain and defend all of it.

M10Server Components & Next.js

Objective: understand the biggest shift in modern React — components that run on the server — and use it in Next.js.

Build: rebuild the spine app in the Next.js App Router with Server Components, Server Actions, and Suspense streaming.

Drill: Turn a client fetch page into a Server Component + Server Action, live. Then: what can a Server Component not do, and why?

Primary: React Server Components, Server Functions; Next.js App Router.

M11Performance at scale & advanced patterns

Objective: find and fix real performance problems, and reach for the right advanced pattern when it earns its keep.

Build: profile a janky 10,000-row list with React DevTools, then make it smooth — virtualization + concurrent features.

Drill: "Typing in this filter freezes the list — fix it." Then: what problem do concurrent features actually solve?

Primary: React docs — useTransition, useDeferredValue, Error boundaries; React DevTools Profiler.

M12System design + interview mastery

Objective: design real front-end systems, type them well, and explain every hard part out loud, under time pressure.

Build: a capstone front-end system design (e.g. a design system / component library, or an infinite feed) + a run of timed mock interviews.

Drill: "Design an autocomplete component used across a big app — talk me through it." Then: a 25-minute live-coding problem, no notes.

Primary: React docs — Using TypeScript; React + TypeScript Cheatsheet; front-end system-design primers; your own 12 builds.
