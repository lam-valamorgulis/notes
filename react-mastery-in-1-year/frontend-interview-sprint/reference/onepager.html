The night before

Everything you need in the last hour. Nothing new — only the things that must arrive without thinking.

Tonight's rule: learn nothing new. Read this page, say your three stories out loud once, check your equipment, and sleep.

The sentences that carry the interview

The render model

"React re-runs my component function to work out what the screen should be, compares that with the last result, and changes only the parts of the DOM that differ. Trigger, render, commit."

Effects

"An effect synchronises my component with something outside React. The dependency array is a declaration of what the setup read — not a schedule."

Redux

"One store, read-only state, and changes only through pure reducers. The UI dispatches a fact; a pure function decides what that fact means."

Context

"Context is a transport, not a store. It answers 'how does this value get there', not 'where does it live'. No selectors, so every consumer re-renders."

Server state

"Client state is mine and always correct. Server state is a copy of someone else's state that may already be wrong. Most 'global state' is really a cache."

Performance

"First I'd measure. Then: too many renders, too much work per render, too much DOM — in that order. Structural fixes before memoisation."

CSS

"Flex is one axis and content-first. Grid is two axes and layout-first. Mobile-first with min-width, so I add complexity as space appears."

Vite

"Vite doesn't bundle in development — native ESM, on-demand transforms, esbuild pre-bundling. It still bundles for production, with Rollup."

Your project

"The engine owns the call; React renders a snapshot of it. Commands go down, state comes back up as events."

Code review

"The bar is whether this leaves the codebase better than it was — not whether it's what I would have written."

The twelve rescue sentences

Didn't understand

  • "Sorry, could you say that again a bit slower?"
  • "Just to check I understood — you're asking about X, is that right?"
  • "I'm not familiar with that term. Could you describe what it does?"

Need a moment

  • "Let me think about that for a second."
  • "There are two ways to look at this. Let me start with the simpler one."
  • "Can I draw this? It's easier to show than to say."

Don't know

  • "I haven't used that. What I do know that's close is…"
  • "I don't know. My guess would be X, and I'd check it by Y."
  • "I'd rather look that up than give you a confident wrong answer."

Lost the thread

  • "Sorry, let me start that again."
  • "The short version is…"
  • "Does that answer it, or would you like me to go deeper?"

The live-coding opening — say this before your first keystroke

"Let me state my assumptions first. [What I'll build, the two or three decisions I'm making, the states I'll handle.] Is that the scope you want, or would you rather I focus somewhere specific?"

Then: never silent for more than about ten seconds. If you are stuck, say what you are stuck on — that sentence is worth more than the decision.

Your six questions

  1. What does the front end look like today — one app or several? Any part everyone is afraid to touch?
  2. How does work reach me — a designed ticket, or am I in the conversation earlier?
  3. What's your testing story on the front end, and are you happy with it?
  4. With a distributed team, how much overlap do people have, and what's expected to be synchronous?
  5. What would a successful first three months look like for this person?
  6. What's the hardest technical problem the front-end team hit this year?

The last sixty seconds

  1. Interest, specific. "This is the kind of front end I want to work on — real product complexity."
  2. One reason you fit. "What I'd bring straight away is React against systems React doesn't control."
  3. Next step. "What are the next steps, and when should I expect to hear?"

The only three things that matter tomorrow
  • Pause one second before every answer. It sounds calm and stops you answering the wrong question.
  • Think out loud. They cannot grade silence.
  • Say "I don't know" cleanly when it is true. It is worth more than a guess, every time.

If you remember one thing: you are not taking an exam. You are showing someone what it is like to work with you.
