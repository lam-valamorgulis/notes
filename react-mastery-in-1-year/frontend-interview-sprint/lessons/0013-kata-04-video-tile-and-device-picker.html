Kata 4 — video tile & device picker

The kata only you can do well. If the interview goes near real-time, ask for this one. 30 minutes.

Your win today: from a blank file you can build a camera preview with a device picker that starts the camera, switches cameras, releases the hardware on unmount, and survives a device being unplugged.

The brief

The task · 30 minutes

"Build a camera preview with a dropdown to choose which camera to use. Like the settings screen before you join a meeting."

Small enough to finish. Deep enough that almost nobody finishes it correctly.

The order that works

Do not start with the dropdown. Start with the stream, because everything else depends on it.

  1. Get one stream on screen. getUserMedia → state → srcObject via a ref.
  2. Add the cleanup before adding any feature. Stop the tracks. Say why out loud.
  3. Enumerate devices and render the dropdown.
  4. Switch on selection — the old stream must stop before the new one starts.
  5. Handle devicechange if there is time. Mention it even if there is not.

The reference shape

function CameraPreview() {
  const [devices, setDevices] = useState<MediaDeviceInfo[]>([]);
  const [deviceId, setDeviceId] = useState<string>('');
  const [error, setError] = useState<string | null>(null);
  const videoRef = useRef<HTMLVideoElement>(null);

  // 1 · one stream, owned by one effect, keyed on the chosen device
  useEffect(() => {
    let cancelled = false;
    let stream: MediaStream | null = null;

    navigator.mediaDevices
      .getUserMedia({ video: deviceId ? { deviceId: { exact: deviceId } } : true })
      .then(s => {
        if (cancelled) { s.getTracks().forEach(t => t.stop()); return; }  // arrived after unmount
        stream = s;
        if (videoRef.current) videoRef.current.srcObject = s;
        setError(null);
        return navigator.mediaDevices.enumerateDevices();     // labels exist only after permission
      })
      .then(list => {
        if (!cancelled && list) setDevices(list.filter(d => d.kind === 'videoinput'));
      })
      .catch(err => { if (!cancelled) setError(explain(err)); });

    return () => {
      cancelled = true;
      stream?.getTracks().forEach(t => t.stop());   // ← releases the hardware, turns the light off
    };
  }, [deviceId]);

  // 2 · hardware can change while we run
  useEffect(() => {
    const onChange = async () => {
      const list = await navigator.mediaDevices.enumerateDevices();
      const cams = list.filter(d => d.kind === 'videoinput');
      setDevices(cams);
      if (deviceId && !cams.some(d => d.deviceId === deviceId)) {
        setDeviceId(cams[0]?.deviceId ?? '');       // our camera was unplugged → fall back
      }
    };
    navigator.mediaDevices.addEventListener('devicechange', onChange);
    return () => navigator.mediaDevices.removeEventListener('devicechange', onChange);
  }, [deviceId]);

  if (error) return <p role="alert">{error}</p>;

  return (
    <>
      <video ref={videoRef} autoPlay playsInline muted />
      <label htmlFor="cam">Camera</label>
      <select id="cam" value={deviceId} onChange={e => setDeviceId(e.target.value)}>
        {devices.map(d => (
          <option key={d.deviceId} value={d.deviceId}>{d.label || 'Camera'}</option>
        ))}
      </select>
    </>
  );
}

The five things to say while you type

When you writeSay
t.stop() in the cleanup"This is the only thing that turns the camera light off. Unmounting doesn't, and clearing srcObject doesn't."
the cancelled flag"getUserMedia is async, so the stream can arrive after unmount. Without this I'd have a live camera and no component."
[deviceId] in the deps"Changing the camera tears down the old stream and builds a new one. The cleanup ordering gives me that for free."
enumerateDevices after getUserMedia"Before permission, the labels come back empty — it's an anti-fingerprinting rule. So the picker is only useful after access is granted."
the devicechange effect"Hardware changes while the app runs. If the selected camera disappears I fall back, otherwise the user gets a black screen with no error."

Errors users actually hit

err.nameWhat happenedWhat to show
NotAllowedErrorPermission denied, or blocked by policyHow to re-enable it in the browser — not "an error occurred".
NotFoundErrorNo camera at all"No camera found. You can still join with audio."
NotReadableErrorAnother app already has the camera"Your camera is in use by another application."
OverconstrainedErrorThe exact deviceId no longer existsRetry without the constraint, then update the list.

Handling three of these by name is far above the bar. Most candidates render one generic message.

Trap — getUserMedia needs a secure context It only works on HTTPS or localhost. Testing on a phone over your local network by IP will fail with no obvious reason. If they ask why it works on your machine and not on the staging IP, that is the answer.
Tick honestly
  • Tracks stopped in the cleanup, and I said why out loud.
  • cancelled flag for the stream that resolves after unmount.
  • Switching device stops the old stream before starting the new one.
  • Named at least three getUserMedia errors and gave each a real message.
  • Mentioned that labels are empty before permission is granted.
  • devicechange handled, or explicitly named as the next thing I would add.
  • <label htmlFor> on the select, and a stable key on the options.

Remember this
  • Build in order: stream → cleanup → device list → switching → devicechange.
  • track.stop() is the only thing that releases the hardware.
  • getUserMedia is async — guard against resolving after unmount.
  • Device labels are empty until permission is granted.
  • Name the errors: NotAllowedError, NotFoundError, NotReadableError, OverconstrainedError.
  • Hardware changes at runtime — listen for devicechange and fall back.
  • Secure context only: HTTPS or localhost.

If you remember one thing: write the cleanup before you write the feature.
