Reference · Nomenclature

Glossary

Node's own vocabulary, defined once and used the same way in every lesson. Each entry gives the precise definition, then a plain-English line, then the week where it starts to matter.

Why a glossary matters here: a lot of Node confusion is vocabulary confusion. "Blocking", "async", "stream" and "worker" all mean something narrower than they sound. Definitions here follow the official Node.js API docs. Where this course picks one word over a common alternative, the alternative is listed as avoid.
Honest note This glossary covers the whole 52 weeks, not only the weeks already written. Terms marked with a later week are here so the vocabulary stays consistent from week 1 — not because they have been taught yet.

The runtime — what Node is made of

Runtime Week 1
The program that runs your JavaScript outside a browser. Node.js is a runtime: it bundles the V8 engine, the libuv library, and a standard library of built-in modules.
Plain English: Node is not a language and not a framework. It is the thing that runs your file.
Avoid: "Node is a framework", "the Node language".
V8 Week 1
Google's JavaScript engine. It compiles and runs your JavaScript, and it owns the heap where your objects live. V8 knows nothing about files, sockets, or timers.
Plain English: V8 does the thinking. It does not do the waiting.
libuv Week 1
The C library that gives Node its event loop, its thread pool, and its non-blocking access to the operating system. Network I/O uses the OS's own event notification; file I/O and some crypto use the thread pool.
Plain English: libuv does the waiting, so V8 never has to.
Thread pool Week 1
A small fixed set of background threads inside libuv (four by default) used for work the OS cannot do without blocking — file system calls, DNS lookups, and some crypto. Network sockets do not use it.
Plain English: a few helpers for jobs the operating system will not do asynchronously by itself.
Avoid: "Node is multi-threaded" — the thread pool does not run your JavaScript.

The event loop and async

Event loop Week 3
The loop that decides what runs next. It moves through fixed phases — timers, pending callbacks, poll, check, close — and runs the callbacks queued in each. Your JavaScript runs on this one thread.
Plain English: a to-do list the runtime works through in a fixed order, forever.
Blocking Week 1
Occupying the event-loop thread so no other callback can run. Any long synchronous computation blocks, and so does every fs.*Sync call. Blocking is measured, not guessed — see event-loop delay.
Plain English: if your code is busy, nobody else gets served. Not slow — stopped.
Avoid: "slow" as a synonym. A slow database query does not block; a slow for loop does.
Macrotask Week 3
A callback scheduled into one of the event loop's phases — a timer, an I/O completion, a setImmediate. One macrotask runs to completion before the next is taken.
Plain English: a normal item on the to-do list.
Microtask Week 3
A callback queued by a promise (.then, await) or by queueMicrotask. The whole microtask queue is drained between macrotasks, so microtasks always run before the next timer.
Plain English: a jump-the-queue item. All of them get done before the next normal item starts.
process.nextTick Week 3
A queue that runs before the microtask queue, and is drained completely each time. Because it is drained completely, a nextTick callback that schedules another one can starve the loop forever.
Plain English: even more urgent than a promise. That is exactly why it is dangerous.
Event-loop delay Weeks 4, 22
How late a timer fires compared with when it was due. It is the honest measure of whether something is blocking. Measured with perf_hooks.monitorEventLoopDelay.
Plain English: how far behind the to-do list has fallen.
Unhandled rejection Week 6
A rejected promise with no rejection handler attached by the time the microtask queue drains. Modern Node treats this like an uncaught exception and terminates the process.
Plain English: an error nobody agreed to catch. Node stops rather than pretend it is fine.
Bounded concurrency Week 7
Running at most N asynchronous tasks at the same time, with the rest queued. The opposite of passing a 5,000-item array straight to Promise.all.
Plain English: ten at a time, not all at once.
Avoid: "throttling" (that is about rate over time) and "rate limiting" (usually enforced by the other side).

Streams and data

Buffer Week 14
Node's fixed-length container for raw bytes, outside the V8 heap. It is a subclass of Uint8Array. Every byte that enters or leaves the process — a file, a socket, a request body — is a Buffer before it is anything else.
Plain English: a box of bytes. A string is what you get after deciding how to read those bytes.
Stream Week 15
An object that moves data in chunks over time, instead of all at once. Four kinds: Readable, Writable, Duplex, and Transform. Every stream is an EventEmitter.
Plain English: a hose, not a bucket. You never hold the whole thing.
Backpressure Week 15
The signal a slow consumer sends back to a fast producer, telling it to stop. In Node this is writable.write() returning false, and the producer waiting for the drain event. Ignore it and data piles up in memory until the process dies.
Plain English: "stop pouring, my glass is full." If nobody listens, the floor gets wet.
highWaterMark Week 15
The buffer size at which a stream says it has had enough — the point where write() starts returning false. It is a threshold, not a hard limit.
Plain English: the line on the glass that means "full".
pipeline Week 16
The function that connects streams and cleans every one of them up when any stage fails. This course uses pipeline and not pipe, because pipe leaves the other streams open on error.
Plain English: pipe with the clean-up that pipe forgot.
Avoid: reaching for .pipe() in production code.

Events, servers, and processes

EventEmitter Week 18
The object that lets other code register callbacks for named events. Emitting is synchronous: every listener runs before emit() returns. Streams, servers, sockets and the process itself are all emitters.
Plain English: "tell me when X happens." Learn it once and four other things stop being mysterious.
Framing Week 19
Deciding where one message ends and the next begins in a byte stream. TCP does not do this for you — two write() calls can arrive as one chunk. HTTP solves it with Content-Length and chunked encoding.
Plain English: TCP gives you letters, not words. Framing is where you put the spaces.
Operational error Week 28
An expected failure in a correct program — a network timeout, a 404, invalid user input, a full disk. You handle these and keep running.
Plain English: something went wrong out there. Deal with it and carry on.
Programmer error Week 28
A bug — reading a property of undefined, a broken assumption, corrupt internal state. You do not handle these. You crash and restart, because continuing with unknown state is how data gets corrupted.
Plain English: the program is wrong. Restarting it is safer than trusting it.
Avoid: catching uncaughtException and continuing.
Graceful shutdown Week 27
On SIGTERM: stop accepting new connections, finish the requests already in flight, close the server and the database pool, then exit — with a hard timeout so shutdown cannot hang forever.
Plain English: finish what you started before you leave.
SIGTERM Week 27
The signal a process manager sends to ask a process to stop. It can be handled. SIGKILL cannot be handled — the kernel ends the process immediately, which is why the work must be done on SIGTERM.
Plain English: "please stop." SIGKILL is "you are stopped."

More than one thread

CPU-bound Week 22
Work limited by processor time — hashing, image resizing, parsing something huge. This is the work that blocks the event loop, and the reason worker threads exist.
Plain English: the computer is thinking hard, so nothing else gets a turn.
I/O-bound Week 22
Work limited by waiting on something else — a network call, a disk read, a database query. Node is built for this, and it does not block the loop.
Plain English: the computer is waiting, not working. Node is very good at waiting.
Worker thread Week 23
A separate thread with its own V8 instance and its own event loop, created with worker_threads. Data is copied between threads unless you transfer it or use a SharedArrayBuffer. Use it for CPU-bound work only.
Plain English: a second Node inside the same process, for the heavy thinking.
Avoid: using a worker thread for I/O — it makes things slower, not faster.
cluster Week 24
A built-in module that forks the whole process once per CPU core, with all forks sharing one listening port. Each fork is a separate process with separate memory — so any in-memory state stops working the moment you cluster.
Plain English: run several copies of your server so all the cores get used.

Modules and the command line

CommonJS Week 9
Node's original module system. require() is an ordinary function, so it resolves a file while the program runs. Everything else follows from that: the path can be computed, the call can sit anywhere, it blocks while reading, and it returns a copy of module.exports.
Plain English: it goes and fetches each file at the moment it reaches that line.
Avoid: "CJS" in prose. Write it out.
ESM Week 9
The JavaScript language's own module system — import and export. It resolves the whole graph before any code runs, in three passes: parse, link, evaluate. That is why imports must be at the top level with a literal path, and why an imported name is a live binding and not a copy.
Plain English: it reads the whole shopping list first, then goes once.
Avoid: "ES modules" and "ESM" used interchangeably in one page. This workspace says ESM.
Specifier Week 9
The string you put in a require() or import. Three kinds, three rules: relative (./util.js), absolute (/opt/app/x.js), and bare (lodash). Only a bare specifier makes Node search.
Plain English: the name you write for the other file.
Bare specifier Week 9
A specifier with no ./ and no leading slash. Node looks for it in node_modules in the current folder, then the parent folder, and up to the root of the disk. NODE_DEBUG=module prints the exact list it checked.
Plain English: a package name. It is the only kind Node has to hunt for.
argv Week 10
The command line, already split into words, as process.argv. Entry 0 is the Node binary and entry 1 is your script, so your own arguments start at process.argv.slice(2).
Plain English: the words the user typed after your program's name.
stdout and stderr Week 10
The two output channels every program is given. stdout carries the answer — the data another program would read. stderr carries everything else: progress, warnings, errors. A pipeline reads stdout only, which is exactly why the split exists.
Plain English: stdout is the result; stderr is you talking to the human.
Avoid: printing a progress message to stdout. It corrupts the data for whatever reads it next.

Surviving a real network

AbortController Week 8
The standard way to cancel work that is already running. You pass its AbortSignal to fetch; when the signal fires, the request is cancelled and its socket is released. AbortSignal.timeout(ms) is the short form.
Plain English: the switch that actually stops the request, not just your waiting.
Avoid: calling a Promise.race against a timer a "timeout". That stops you waiting; the request carries on.
Exponential backoff Week 8
Waiting longer before each retry — 200 ms, then 400, then 800. A failing server is usually a busy server, so retrying immediately adds load at the worst possible moment.
Plain English: if it failed, wait a bit. If it failed again, wait longer.
Jitter Week 8
A small random amount added to each backoff wait. Without it, every client that failed at the same moment retries at the same moment, and the recovering server is knocked over again — the thundering herd.
Plain English: everyone waits a slightly different amount, so they do not all come back together.

Production

Retainer Week 32
The reference that stops an object being garbage collected. Finding a memory leak means finding the retainer path in a heap snapshot — not just noticing that memory grew.
Plain English: whoever is still holding on. Until they let go, the memory stays.
Heap snapshot Week 32
A dump of every object V8 is holding, at one moment. Leaks are found by diffing two snapshots taken some time apart and reading what grew.
Plain English: a photo of memory. Two photos show what is piling up.
p99 Week 31
The latency that 99% of requests came in under. This course reports p50, p95 and p99 — never an average alone, because an average hides the requests that made a user leave.
Plain English: how slow it is for your unluckiest users.
Avoid: "average response time" as the headline number.
Idempotency Week 42
The property that doing an operation twice has the same effect as doing it once. It is required with a job queue, because queues deliver at least once — so a retry can and will run a job a second time.
Plain English: pressing the button twice must not charge the customer twice.
Cache stampede Week 41
What happens when a popular cache key expires and every waiting request hits the database at the same instant. Also called a thundering herd.
Plain English: the cache empties and everyone runs at the database at once.
Connection pool Week 40
A fixed set of open database connections shared by all requests. When every connection is busy, new requests wait — which looks like a hang with an idle CPU.
Plain English: a small set of phone lines to the database. When they are all in use, you queue.

Course words — used with one fixed meaning here

The spine Week 21 →
The one API built in week 21 and hardened every week after. In this workspace "the spine" always means that service, never a general idea.
Plain English: the project you keep. Do not start a new one.
core All weeks
One of the twelve items in the 20% core. A core week is never skipped, and no depth week starts while a core week is untaught.
Plain English: the part you must have.
depth All weeks
Real and useful, but not touched weekly by a Node backend engineer. Queued, never deleted. Shown with a dashed border on the plan.
Plain English: worth learning, later.
Avoid: treating depth as "optional forever". It is scheduled, not dropped.
Review week 13, 26, 39, 52
A week with no new material. Retrieval practice from memory, questions interleaved across earlier weeks, and one mock interview. The spacing is the point.
Plain English: no new pages. Prove you still remember the old ones.
