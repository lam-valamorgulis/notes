The 12-Month Plan

One page that holds the whole year. Four phases, twelve monthly modules, one real build each. Tick each skill when you can do it — not when you have read about it.

How to use this: The Map tells the story; this page tracks what to tick off. Each month has a real build (the use case), a few skills, and one live-coding / interview drill. Your ticks are saved in this browser automatically.

Progress: 0 / 0 skills ticked

Pacing at ~10 hrs/week Roughly: ~2 hrs on the lesson (first principles), ~1 hr reading the primary docs, and ~6–7 hrs building the real project and doing the drills. This course is build-first on purpose — you learn the hard parts by hitting them in real code, then say them out loud until an interviewer can't shake you.

Phase 1 · Months 1–3 · Foundations

Build your JavaScript and Node footing through small, real tools.

M1Foundations & the event loop

Objective: understand what Node.js is, why one thread serves thousands, and the one rule you never break.

Build: a responsive web server (raw http) with a fast and a slow route, plus a tiny latency tester — prove async vs blocking under load.

Drill: Whiteboard the print order for sync + setTimeout(fn,0) + Promise.resolve().then(fn), and explain microtask vs macrotask.

Primary: Node docs — Introduction, Don't Block the Event Loop. Lessons: 0001, 0002, 0003, 0004.

M2Async mastery

Objective: move fluently from callbacks to promises to async/await, handle errors, and run many things at once safely.

Build: a concurrent multi-API aggregator — fetch hundreds of URLs with a concurrency limit, retries with backoff, and timeouts.

Drill: Given 500 URLs, fetch them 10 at a time with retries — write it live. Then: Promise.all vs allSettled — when does each fail you?

Primary: Node docs — Asynchronous flow; MDN — Promises & async/await. Lessons: 0005, 0006, 0007, 0008.

M3Modules, packages & a real CLI

Objective: understand how Node loads code, and ship a real command-line tool as a package.

Build: a command-line tool (e.g. bulk file renamer / project scaffolder) and publish a small npm package that works as both CommonJS and ESM.

Drill: Build a CLI that renames files by a pattern, live. Then: why can require and import of the same file behave differently?

Primary: Node docs — CommonJS, ESM, process; npm docs.

Phase 2 · Months 4–6 · The hard core

The parts people fear: streams, servers from raw sockets, and real concurrency.

M4Streams, buffers & backpressure

Objective: move data that is far too big to fit in memory, safely and at full speed.

Build: a multi-GB CSV/log processor using Transform streams + pipeline that runs in constant memory; plus chunked hashing of a huge file.

Drill: Transform a 5 GB CSV to NDJSON with memory staying flat — write the pipeline live. Then: what is backpressure, and who applies it to whom?

Primary: Node docs — Stream, Buffer, Backpressuring in Streams.

M5Events + servers from scratch

Objective: understand the event system Node is built on, and build a web server and a TCP server with no framework.

Build: a REST API from the raw http module (this becomes the "spine" you harden all year) + a raw-TCP chat server (net) + an internal EventEmitter bus.

Drill: Implement routing + JSON body parsing on the raw http module, live (no framework). Then: why must you always handle 'error' on an EventEmitter?

Primary: Node docs — Events, HTTP, Net.

M6Worker threads, child processes & cluster

Objective: do CPU-heavy work without freezing the event loop, and use every core on the machine.

Build: an image-thumbnail service with a worker-thread pool (CPU offload), then scale the spine API across all cores with cluster; load-test before vs after.

Drill: Offload image resizing to a worker pool so the API stays responsive — sketch it live. Then: does cluster give workers shared memory? What do they actually share?

Primary: Node docs — Worker threads, Child process, Cluster.

Phase 3 · Months 7–9 · Production-grade Node

Turn a program that works into a service that survives real traffic.

M7Reliability & performance

Objective: make the service crash-safe and fast, and be able to hunt a real performance problem.

Build: harden + load-test the API (graceful shutdown, health checks), then find and fix a planted memory leak under load.

Drill: "Your service's memory climbs until it crashes nightly — walk me through finding the cause." Then: what should uncaughtException actually do?

Primary: Node docs — Signals, Diagnostics: Memory; Chrome DevTools inspector.

M8Testing, debugging & security

Objective: prove your code works, debug like an engineer (not with console.log), and close common holes.

Build: a full test suite (unit + integration) for the API and the stream processor, a real inspector debug session, and a security pass.

Drill: Write a failing test for a bug first, then fix it — live. Then: name three ways untrusted input can hurt a Node server.

Primary: Node docs — Test runner, Debugger; OWASP Node.js cheat sheet.

M9Databases, caching & queues

Objective: give the service real persistence, real caching, and real background work.

Build: add Postgres (persistence), Redis (caching), and a background job queue (retries) to the API.

Drill: Add a background email job with retries — design it live. Then: name a case where caching makes correctness worse.

Primary: node-postgres, Redis, BullMQ docs.

Phase 4 · Months 10–12 · TypeScript, NestJS & the interview

Make it professional, then be able to explain and defend all of it.

M10TypeScript for Node

Objective: add a type system that catches bugs before they run — the required step before NestJS.

Build: migrate the whole API to TypeScript, with a real build and a type that would have caught a real bug.

Drill: Migrate one module to TypeScript live and justify every type you add. Then: what does strict mode actually turn on?

Primary: TypeScript Handbook; typescript-eslint.

M11NestJS — the professional rebuild

Objective: rebuild the platform the way a real team would — structured, testable, and maintainable.

Build: rebuild the platform in NestJS with modules, dependency injection, guards, pipes, interceptors, a database, and tests.

Drill: "Why does NestJS use dependency injection — what pain does it remove?" Then: build a guarded route with a validated DTO, live.

Primary: NestJS docs — Overview, Techniques, Testing.

M12System design + interview mastery

Objective: design real systems and explain every hard part out loud, under time pressure.

Build: a capstone system design (e.g. a URL shortener or notification service at scale) + a run of timed mock interviews.

Drill: "Design a service that sends 1M notifications/hour — talk me through it." Then: a 25-minute live-coding problem, no notes.

Primary: Node.js Best Practices; system-design primers; your own 12 builds.
