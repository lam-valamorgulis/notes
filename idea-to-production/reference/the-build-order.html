The build order

All 24 weeks on one page. Print it. Tick the gates.

How to read this. Twelve blocks of two weeks. Each block has one core Lesson, two depth Lessons, and one artefact — a thing that exists at the end. Each Stage ends with a gate: one sentence that must be true before the next Stage starts.

Why this order and not another

The order follows how expensive a mistake becomes, cheapest first.

A wrong sentence in a design doc costs a rewrite of that sentence. A wrong column in a schema, two years later, with ten million rows in the table, costs a six-week migration. So writing comes before schema, and schema comes before pipelines.

Delivery comes before operations for a duller reason. You cannot watch a thing that is not deployed. Stage 4 needs Stage 3 to have happened.

Ours, not a source's No source says "spend four weeks on deciding". The four Stages and the two-week block are this course's own structure. The ideas inside each block are sourced individually, in RESOURCES.md. Do not quote the schedule as if someone researched it.

The four gates

A gate is pass or fail. There is no "mostly". Each one names the failure it catches.

AfterThe gateWhat failing it means
Week 4 A design doc for Speck exists, another person has read it, and it names an option you rejected with the reason. You are building by instinct. The first hard trade-off will be argued in code instead of on a page.
Week 10 Schema, public API and config are written down, and someone who has never seen Speck runs it locally in 30 minutes. Only your laptop can build it. That is not a product, it is a hobby with a URL.
Week 18 A commit reaches production with nobody touching a server, and you have rolled a release back on purpose. Every deploy is a small ceremony, so you will deploy rarely, so each deploy will be large, so each one will be risky.
Week 24 Speck was broken on purpose, an alert reached your phone, and the postmortem is written. You will find out about outages from users. The course is not finished.

If you fall behind

Two weeks per block is a plan, not a promise. When a block runs long, the fix is always the same: keep the artefact, shrink the scope.

The artefact is the point. A design doc for one Speck feature still passes Gate 1. A pipeline with two stages instead of five still passes Gate 3. A half-finished block with no artefact passes nothing.

The failure this catches Reading all twelve Lessons in three weeks feels productive and teaches almost nothing. Retrieval and spacing are what make knowledge stick. The two-week block exists to force the gap between reading and using.
Think a Stage is in the wrong place? Say so, with the reason. If the order is wrong for your real situation, we change it and write a learning record explaining the change.
