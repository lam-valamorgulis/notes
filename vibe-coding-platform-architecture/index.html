Vibe Coding Platform

One real open-source agent product, understood end to end in 30 days — so you can draw it, defend it, and criticise it out loud in an AI Engineer interview.

The mission: know Vercel's vibe-coding-platform well enough to survive a 45-minute interview on it. Full detail in MISSION.md. The plan below is 30 days × 2 hours.

The big picture

Strip away the marketing and this product is two things: a tool-calling loop and a throwaway virtual machine. A language model is handed four tools — make a machine, write files into it, run a command, expose a URL — and everything on screen follows from those four verbs.

But you cannot read the code until you can read the framework. So the month starts with Next.js as this repo actually uses it: the line between server and browser, which is also the line that keeps the API key safe, and the six endpoints that make up the entire back end — none of which use a WebSocket, all of which stream over plain HTTP. Week 1 exists because the first version of this course skipped it, and that was the biggest gap the review found. The review is in GAPS.md.

With the framework in hand, Week 2 gets to the genuinely clever part: the streaming contract. Every tool reports what it is doing twice, in two languages — a typed object for your screen, a prose sentence for the model's next decision. Once you see that split, the interface stops looking like magic. The file tree, log panel and preview are not watching the chat; they are watching a typed event stream. That is why state lives in three places at once — nothing on the server, a small store in the browser, and the only real truth inside a machine that is about to die.

Week 3 turns the five features into variations on one theme. The sandbox lifecycle is a study in living with something ephemeral. File generation hides the most surprising decision in the repo — a second model call nested inside a tool — plus a deliberate off-by-two that stops half-written files being uploaded. Running commands needs its own log channel that bypasses the agent. The live preview is one React trick. And the auto-fix loop closes the circle: the app reads its own errors, summarises them with another model, and feeds them back as a new user message — behind four separate brakes.

Only then do the trade-offs mean anything, because a cost is meaningless until you know what it bought. Week 4 covers them, the full stack on both sides, and the question that decides senior interviews — "what would you change?" — before the closing mock interview drills all of it against the clock.

How each 2-hour session works

Same shape every day. The last block is the one that matters most, and the one most people skip.

One honesty rule for this course There is no official architecture write-up for this app — no blog post, no design doc. Every trade-off in these lessons is read from source code, not quoted from the authors. In an interview, frame it as "reading the code, my read is…" and never as "Vercel says…". The one exception is the sandbox status hack, where the maintainers left a comment admitting it — quote that freely.
