Rate limits and throttles card

All the numbers in one place, each with the date it was checked.

Read this before quoting any number below These move. The daily variant throttle changed by a factor of ten between two checks three weeks apart in August 2026. Everything here was verified on 2026-08-23. If you are reading this more than a month later, re-check before it goes in a proposal — and say the date when you quote it.

GraphQL Admin API — a cost budget

ThingValue
ModelCalculated query cost in points. Not a request count
Documented example bucket1,000 points, restore 50/second. Scales with plan tier
Field costsscalar 0 · enum 0 · object 1 · mutation 10 · connection sized by first/last
Before executionBucket must hold the requested cost
After executionRefunded the difference between requested and actual
Single query ceiling1,000 points, any plan, checked before execution. Waiting never helps
Input array size250 items
Throttled responseHTTP 200 OK with errors[].extensions.code = "THROTTLED" and actualQueryCost: null
Where to read your budgetextensions.cost.throttleStatus → maximumAvailable, currentlyAvailable, restoreRate — present on successes too
The one that catches everyone if (response.ok) is not an error check on this API. Throttles, validation failures and partial successes all return 200. Check HTTP status, then errors[], then data.*.userErrors[].

The extra variant throttle

RuleValue
Threshold500,000 product variants on the store
ThenNo more than 10,000 new variants per day
PlusExempt
AffectsproductCreate, productUpdate, productVariantCreate, and the matching REST product endpoints

History: on 2026-08-03 two Shopify pages disagreed — one said 50,000 / 1,000 per day, the other 500,000 / 10,000. Re-checked 2026-08-23: they agree on the looser figures above. This number has moved once. Measure on the client's real store before sizing a project.

The well-behaved worker

loop: if (currentlyAvailable < nextQueryCost + margin) sleep((nextQueryCost - currentlyAvailable) / restoreRate) send read extensions.cost.throttleStatus ← on success as well currentlyAvailable = that ── this is a SPEED LIMITER, not error handling. being throttled means the limiter failed. classify before retrying: transient (5xx, timeout) → backoff WITH JITTER throttled → wait for budget. honour Retry-After on REST terminal (userErrors) → DEAD-LETTER IMMEDIATELY. never retry poison (N identical fails)→ dead-letter with the full body
